# LLM 추가 기능 후보 16개 (리그전 심사용 정리)

아이디어 3~5회차에서 통과한 후보를 같은 형식으로 정리했습니다. **아직 구현하지 않은 후보**이고, 효과는 모두 추정입니다. 자세한 내용과 탈락한 회차는 `docs/ideas-llm.md`에 있습니다.

## 서비스 한 줄
시간은행 + LLM 돌봄 플랫폼 "시간 적금". 이웃을 도운 시간만큼 통장에 쌓이고 나중에 그 시간으로 도움을 받는다. 1시간 = 1시간. 5060이 지금 쌓고 7080에 받는다. 가벼운 봉사 6종(말동무·디지털 도움·생활 정리·장보기·가벼운 집안일·동행)만. 주민센터 담당자가 계정 없는 독거노인을 대신 관리. 수락·등록·제재·적립 같은 결정은 사람이 한다(자동 매칭 없음). 진단·건강 판단 금지. AI 말벗 금지.

## 이미 구현된 LLM 기능 (차별화 판단 기준)
대화형 공고 작성 / 말로 요청하기(음성 → 요청서) / 금지 요청 판정 / 난이도 제안 / 활동 일지 정리 / 공공 서비스 안내 / AI 도움 추천 / 교육 역할극 / 요청서 빠진 정보 점검 / "왜 이 봉사자?" 추천 이유 한 줄 / 미매칭 공고 고치기 제안 / 공고 쉬운 말로 듣기 / 음성 비서 "물어보기"(잔액·일정을 답하고 일부 화면을 열어 줌, 실행은 안 함) / 전화 알림 문장(전화 연결은 흉내) / 방문 전 브리핑 카드 / 메시지 안전 감지 / 빠른 답장·일정 변경 감지 / 시간 조정·이의 판단 보조 / 적립 목표 코치·봉사 플랜 / 월별 결산 설명 / 내 활동·평가 습관 분석 / 전달 메모 정리·생활 변화 신호 / 담당자 통화 메모 → 공고 여러 건(대상 한 명씩) / 담당자 주간 브리핑(읽을거리) / 맞춤 역할극 상대 만들기 / 신고 정리·우선순위(신고 글 한쪽만 요약) / 이상 적립 패턴 설명 / 문의 답변 초안 / 운영자 인사이트 / 인수인계 요약 / 기관 클래스 추천 / 서버 음성 인식

### 2026-11-11~12에 추가로 구현된 것 (차별화 판단에 포함)
역할별 정리판 프로토타입 반영으로 다음이 **이미 구현됨**: 헤더의 도움 받기/봉사하기 전역 모드 / **플래너**(캘린더 · 추천 봉사(내 시간·지역에 맞는 열린 요청을 골라 달력에 넣기) · **생애 플랜**(지금 나이·받기 시작할 나이·한 달 모을 시간·받고 싶은 도움 → 몇 살까지 받을 수 있는지, 나이별 통장 그래프, AI 조언)) / **AI 도움 추천 2섹션**(받을 수 있는 도움 설명 + 단골 추천 + 가까운 사람 추천) / 동네 기관 소식 근처 지역 정렬 / **카테고리 추가 건의**(사용자·담당자 → 운영자) / 담당자 대리 공고의 관리 대상 이슈 칸 / 봉사 인증 항목 설정 화면 / 받은 도움 기록.

## 후보 16개

### F01 전화 창구
- **무엇**: 앱을 못 쓰는 어르신에게 서비스가 전화를 걸어 용건을 말하고, 대답을 알아듣고, 본인 결정을 받아 온다.
- **장면**: "김복남 님, 최미경 님이 18일 오후 두 시 병원 동행을 해 주시겠대요. 받으시겠어요?" / "근데 그날 세 시로 바뀌었는데." / "세 시도 되는지 여쭤볼까요? 맞으면 1번을 눌러 주세요." → 봉사자에게 갈 일정 변경 메시지 초안 생성.
- **LLM이 하는 일**: 통화 1건에 3~6번. 용건 대본 → 턴마다 음성 이해(수락·거부·시간 변경·되묻기·새 요청·위급) → 일정·잔액을 찾아 답 → 복창 → 통화 결과 정리. LLM이 없으면 "1번 수락, 2번 거부" 자동응답기만 남는다.
- **필요한 이유**: 최종 수락을 24시간 안에 안 하면 요청이 만료된다. 받는 쪽이 7080인데 앱 알림을 못 보면 요청이 죽고 시간이 돌지 않는다. 지금은 음성 전화 알림이 흉내(서버 기록)뿐이다.
- **약점**: 실제 전화는 전화망 업체 계약과 통화료가 필요(시연은 화면 안 통화 흉내). 사투리·고령 목소리 인식률은 써 봐야 안다. 크기 중~대.

### F02 주간 돌봄 편성표
- **무엇**: 담당자가 버튼을 누르면 담당 어르신 전원의 한 주 편성안(누가 언제 누구에게)이 이유와 함께 나오고, 말로 고친 뒤 한 번에 보낸다.
- **장면**: 어르신 12명 × 요일 표. "이순례 님 목 오전 말동무 → 최미경 님(단골, 같은 동)". 빈칸에는 대안. 담당자: "박 어르신은 병원 가시니 목요일 빼 줘." → 다시 짜짐 → "9건 보내기".
- **LLM이 하는 일**: 주 1회 3~4번 + 수정마다 1번. 주의사항·전달 메모·방문 기록에서 이번 주 할 일 뽑기 → 전체 배정과 이유·빈칸 대안 → 말로 고친 내용 반영. 시간 겹침 등 규칙 위반은 코드가 거른다.
- **필요한 이유**: 독거노인은 기관을 통해서만 들어온다. 지금은 담당자가 건별로 처리해 어르신이 늘수록 일이 는다. 기관이 도입할 이유.
- **약점**: 가장 큰 편. 어르신 5명 이하 기관은 체감이 작다. 편성 품질은 실데이터로 확인해야 한다.

### F03 돌봄 설계
- **무엇**: "엄마가 다음 주 금요일에 퇴원하세요" 같은 상황 한마디를 2주치 돌봄 계획(가벼운 일 여러 건의 일정 + 필요 시간 합계와 내 잔액 + 못 하는 일은 공공 서비스 연결)으로 짜고 버튼 하나로 묶음 등록.
- **장면**: 되묻기 2번("장은 누가 봐 드리나요?") → 퇴원 날 동행, 장보기 주 2회, 집안일 주 1회, 말동무 주 2회, 재진 동행. 합계 17.5시간 / 잔액 24.5시간. "목욕은 못 해요 → 노인맞춤돌봄서비스 안내". "9건 올리기".
- **LLM이 하는 일**: 계획 1건에 3~5번. 상황 이해 → 가벼운 일로 쪼개기(금지 필터 통과) → 일정 배치·줄인 안 → 안 맞춰지면 다시 짜기.
- **필요한 이유**: 5060이 가입하는 현실적 계기는 지금 부모에게 일이 생긴 순간. "내가 쌓은 시간으로 엄마의 2주가 채워진다"를 한 화면으로 보여 준다.
- **약점**: 봉사자가 부족하면 계획만 크고 매칭이 안 된다. 부모 대신 쓰려면 서버의 가족 대리 처리가 새로 필요. 크기 중~대.

### F04 봉사 개통
- **무엇**: 가입 첫날 3분 말 인터뷰로 프로필을 만들고, 신분증 승인이 나는 순간 보낼 "첫 달 봉사 묶음"을 미리 짜 둔다.
- **장면**: "은행 30년 다니다 퇴직했어요. 화·목 오전이 비고 무릎이 안 좋아요." → 준비표: 소개문, 디지털 도움·말동무, "장보기는 뺐어요(무거운 짐)", "은행 업무 대신은 금지예요", 승인되면 보낼 공고 4주치 + 열린 요청 2건 제안 → 승인 알림에서 "준비해 둔 6건 보내기".
- **LLM이 하는 일**: 가입자당 5~7번. 인터뷰 되묻기 → 프로필 구조화(제외할 일과 이유) → 첫 봉사에 맞는 요청 고르기 → 승인 시점 재확인.
- **필요한 이유**: 시간은 누군가 첫 봉사를 해야 생긴다. 지금은 가입과 첫 봉사 사이에 승인 대기가 끼어 있고 그동안 붙잡는 것이 없다.
- **약점**: 60대가 가입 직후 3분을 말할지 모른다. 열린 요청이 적은 동네에서는 준비표가 빈약. 크기 중.

### F05 지금 물어보기
- **무엇**: 봉사 중 곤란한 부탁을 봉사자가 말로 물으면 되는지/안 되는지, 어르신께 할 말, 대신 할 수 있는 일을 바로 준다.
- **장면**: "어르신이 통장이랑 도장 주시면서 30만 원만 찾아다 달라세요." → "안 돼요. 돈·통장을 맡는 일은 금지예요. 이렇게 말씀해 보세요: '어머니, 저희는 돈 심부름은 못 하게 돼 있어요. 은행에 같이 가 드리는 건 돼요.'" + 은행 동행 요청 초안 / 담당자에게 알리기.
- **LLM이 하는 일**: 질문당 1~2번. 말 + 이 요청의 주의사항 + 규칙 카드를 읽고 허용·주의·불가, 근거, 할 말, 후속 조치. 코드의 금지 규칙이 먼저 돌고 AI는 수준을 내리지 못한다.
- **필요한 이유**: 규칙이 닿는 때가 교육·글 쓸 때·방문 전뿐이고 현장이 비어 있다(활동 중 화면에는 QR과 긴급 버튼만). 기관이 묻는 "현장에서 선 넘는 일은 어떻게 막나"의 답.
- **약점**: 금지 판정 엔진의 재사용이라 새로움이 약하다는 반론. 봉사 중에 폰을 꺼낼지 모른다. 크기 소~중(가장 작음).

### F06 기관 이사 들이기
- **무엇**: 기관의 대상자 장부(엑셀·수기)를 올리면 실명·주소·전화는 버리고 별칭·동·필요한 도움·주의사항·정기 공고 초안으로 바꿔 한 번에 등록한다.
- **장면**: 32명 엑셀 → "이○례 · 희망동 · 말동무·장보기 · 큰 소리로 말씀해 주세요 / 반려견 있음 · 매주 목 오전 말동무". 빨간 줄: "목욕 보조 → 금지, 방문목욕 서비스 안내", "병명은 옮기지 않았어요" → "29명 등록 + 정기 공고 초안 41건".
- **LLM이 하는 일**: 기관당 5~7번. 열 의미 맞추기 → 특이사항 글을 병명 없는 주의사항으로 바꾸기 → 방문 주기를 6종 봉사와 금지로 가르기.
- **필요한 이유**: 지금은 어르신을 한 명씩만 등록할 수 있어, 기관이 도입을 결정해도 수십 명을 손으로 옮겨야 시작된다.
- **약점**: 장부에 개인정보가 들어 있어 무료 AI로는 실사용 불가(유료 등급 전제). 기관이 장부를 올려도 되는지 법무 확인 필요. 크기 중~대.

### F07 정책 실험실
- **무엇**: 운영자가 시간 화폐에 대해 말로 묻고 규칙을 가상으로 바꿔 보면, 코드가 원장을 다시 계산하고 AI가 안 비교표와 공지 초안을 낸다.
- **장면**: "10시간 조건을 5시간으로 낮추면?" → 지난 6개월 기록에 가상 규칙 적용 비교표. "조건에 막혀 포기한 요청은 기록이 없어 알 수 없어요." → 안 A·B·C의 영향·위험·공지 초안.
- **LLM이 하는 일**: 세션당 4~8번. 질문 → 조회 계획 → 결과 해석 → 후속 질문 → 안 비교. 숫자는 코드가 낸다.
- **필요한 이유**: 독거노인 건은 차감 없이 발행만 돼 발행이 소비보다 많다. "20년 뒤에도 이 시간이 가치 있나"에 대한 운영 쪽 답, 지자체 설득 자료.
- **약점**: 회원 데이터가 쌓이기 전에는 실효가 없다. 일반 사용자에게 직접 보이는 것이 없다. 크기 대.

### F08 분쟁 조정실
- **무엇**: 신고가 오면 AI가 기록에 근거한 질문으로 상대 쪽 이야기를 받고, 일치·엇갈림·기록 대조표와 조치별 안내문 초안을 운영자에게 낸다(판정은 안 함).
- **장면**: "봉사자가 30분 일찍 갔다" 신고 → 봉사자에게 "끝 체크가 14:32로 찍혀 있어요. 그때 상황을 말씀해 주세요." → 대조표: 일치(14:30경 종료), 엇갈림(누가 끝내자고 했나), 기록(14:28 메시지).
- **LLM이 하는 일**: 사건당 약 5번. 기록 기반 질문 생성 → 양쪽 답 정리 → 대조표 → 안내문.
- **필요한 이유**: 지금은 운영자가 조치를 고르면 봉사자에게 통보만 간다. 억울한 경고 한 번에 봉사자가 떠날 수 있다.
- **약점**: 사건이 드물면 눈에 띄지 않는다. 일반 사용자 대부분은 볼 일이 없다. 크기 중.

### F09 여기 눌러요
- **무엇**: 어르신이 어느 화면에서든 "이거 으뜨케 혀~" 하고 말하면 AI가 해당 화면으로 데려가고 누를 버튼을 짚어 소리로 안내한다.
- **장면**: (요청 상세에서) "이거 으뜨케 혀?" → "김하늘 학생이 수요일 두 시에 병원 같이 가 주겠대요. 받으시려면 아래 초록색 '최종 수락'을 누르세요."(버튼 반짝) / "시간 냄겨 놓은 거 딸한테 주고 싶은디" → 통장 → 가족 고르기 → 시간 → 보내기를 한 단계씩 짚어 줌.
- **LLM이 하는 일**: 말(사투리, "이거·그거") + 지금 화면 + 그 사람의 현재 상황(요청 단계·잔액·일정)을 함께 읽어 갈 화면과 짚을 버튼, 안내 문장을 낸다. 누르는 것은 어르신.
- **필요한 이유**: 받는 쪽이 7080인데 앱을 못 쓰면 요청·수락·확인이 안 된다. 앱 안의 통로. 사진이 필요 없어 개인정보 문제가 없고 무료 AI로 된다. 우리 화면과 상태는 우리만 안다.
- **약점**: 지금 있는 "물어보기"와 겹친다(물어보기를 키우는 형태). 엉뚱한 버튼을 짚을 위험. 사투리 인식률. 크기 중.

### F10 다녀간 뒤 한마디
- **무엇**: 봉사자가 다녀간 뒤 어르신이 한마디 하면 확인·평가·단골·다음 약속(또는 불편 접수)까지 한 장으로 짜서 내밀고 한 번에 승인받는다.
- **장면**: "아이고 그 처자 참 싹싹혀. 약 타는 것도 다 챙겨 주고. 담 주에도 또 왔으면 좋겄는디." → 한 장: ① 오늘 2시간 확인 ② 별 5개·"꼼꼼해요" ③ 단골 등록 ④ 다음 주 수요일 2시 같은 도움 요청. "별은 됐고 나머지는 그려." → "이대로 하기". 반대로 "한 시간도 안 있다 갔어, 자꾸 전화번호를 달래" → 확인 미루기 + 운영자 알림 초안.
- **LLM이 하는 일**: 1건에 1~2번. 어르신 말 + 요청 정보 + 일지를 읽고 계획(확인 여부, 태그, 단골, 다음 약속 날짜, 불편 유형)을 낸다. 실행은 버튼 뒤 기존 기능으로.
- **필요한 이유**: 재요청과 단골이 서비스가 계속 도는 고리인데, 지금은 가장 서툰 사용자에게 화면 4개로 맡겨져 있다. 24시간 뒤 자동 확정되면 평가가 비고 불편이 묻힌다.
- **약점**: 평가 부분만 보면 예전에 퇴짜 맞은 "평가를 한마디로"와 같다. 어르신이 활동 직후 앱을 열지 모른다. 크기 중.

### F11 말로 한 바퀴
- **무엇**: 글이 안 보이는 어르신이 "뭐 왔어?" 한마디로 밀린 일을 급한 순서대로 듣고, 하나씩 말로 답해 끝낸다(화면을 안 봐도 됨).
- **장면**: "뭐 온 거 있어?" → "세 가지 있어요. 첫째, 김하늘 님이 수요일 두 시에 병원 같이 가 주겠대요. 내일 낮까지 답하셔야 해요." / "수요일이 며칠이여?" / "십일월 십팔일이에요." / "그려, 오라 혀." → 복창 → "맞어." → "됐어요. 둘째, 딸이 세 시간을 선물했어요…"
- **LLM이 하는 일**: 한 바퀴에 2~5번. 대기 목록의 급한 순서와 읽을 문장 → 턴마다 수락·거부·나중에·되묻기·위급 가르기, 되묻기에 답하기. 실행은 복창 뒤 "맞아요"나 버튼.
- **필요한 이유**: F09는 화면을 볼 수 있는 사람용, F01은 전화망 계약이 필요. 이것은 폰은 있지만 글을 못 읽는 사람의 통로이고, F01과 같은 대화 엔진을 통화료 없이 먼저 검증한다.
- **약점**: F01·F09와 엔진·입구가 겹친다(한 엔진의 다른 입구). 잘못 알아듣고 수락할 위험. 크기 중~대.

### F12 같이 가요
- **무엇**: 어르신이 동네 소식·기관 강좌를 듣고 "가고 싶은디 혼자는 못 가" 하면 신청과 강좌 날짜에 맞춘 동행 요청 묶음을 한 번에 짜 준다.
- **장면**: "요새 동네에 뭐 허는 거 없어?" → 세 가지 읽어 줌 → "첫 번째 거. 근디 혼자 못 가." → 스마트폰 교실 신청 + 화요일 동행 요청 4건, 필요 10시간 / 잔액 12시간. "처음 두 번만." → 2건으로 → "이대로 올리기".
- **LLM이 하는 일**: 1건에 2~3번. 강좌 후보에서 맞는 3개 고르기 → "매주 화 10시, 11.17~12.8" 같은 일정 문장을 날짜로 풀고 말과 합쳐 묶음 만들기 → 고침 말 반영.
- **필요한 이유**: 기관 강좌 참석이 늘면 기관이 이 앱을 쓸 이유가 된다. 병원 말고도 부담 없는 동행 수요가 생긴다.
- **약점**: F03과 묶음 등록 엔진이 같다. "혼자 못 가서 안 가는" 어르신이 얼마나 되는지 모른다. 10시간 조건 때문에 새 7080은 쓸 시간이 없을 수 있다. 크기 중.

### F13 부모님 모셔 오기
- **무엇**: 멀리 사는 자녀가 "쓸 계획이 든 시간 보따리"를 보내면, 부모 폰에서 말 몇 마디로 가입 마무리·가족 연결·첫 요청까지 끝난다.
- **장면**: 딸: "엄마한테 네 시간 보낼게. 수요일마다 병원 갈 때 누가 같이 가 주면 좋겠어." → 엄마 폰이 소리로: "따님이 네 시간을 보냈어요. 수요일 병원 갈 때 쓰시라고요. 받으실래요?" / "아이고, 그려." / "병원은 몇 시에 가세요?" / "열 시 반." → 요청서 → "이대로 올리기".
- **LLM이 하는 일**: 보따리 1개에 3~4번. 자녀 말에서 시간·용도·반복 뽑기 → 부모에게 쉬운 말로 읽고 빠진 것 묻기 → 요청 초안과 프로필 채우기.
- **필요한 이유**: 5060 가입자 한 명이 7080 한 명을 데려오는 길. 선물받은 시간은 10시간 조건에 안 걸려 새 7080이 바로 쓸 수 있다. 등록·수락은 부모 계정에서 부모가 하므로 가족 대리 문제를 돌아간다.
- **약점**: 가입 안 한 사람에게 선물을 약속하는 것은 정책 변경. 부모가 문자 링크를 못 누를 수 있다. 무료 AI 실사용에 걸린다. 크기 대.

### F14 대타 잇기
- **무엇**: 봉사자가 "내일 못 가요" 하거나 어르신이 "안 와" 하면 약속을 죽이지 않고 대신 갈 사람 후보와 인수 메모까지 짜서 양쪽 승인으로 잇는다.
- **장면**: "내일 김순자 님 댁 못 가게 됐어요." → "취소하면 약속이 사라져요. 대신 갈 분을 먼저 찾아볼까요?" → 후보 3명과 이유, 인수 메모 초안("장보기 2시간, 벨 대신 노크") → 한 분이 수락 → 어르신에게 "내일은 이영수 님이 가도 될까요?" + 소개 카드.
- **LLM이 하는 일**: 1건에 2~3번. 말에서 어느 약속인지 가리기 → 후보 순서·이유·인수 메모 쓰기 → 아무도 없으면 날짜 옮기는 안. 후보 조회 자체는 코드로 된다(LLM 의존도 중간).
- **필요한 이유**: 지금은 취소하면 약속이 죽고 봉사자에게 패널티가 붙는다. 어르신에게는 헛걸음, 봉사자에게는 그만둘 이유.
- **약점**: 핵심 가치가 봉사자 교체 로직(코드)에 있다. 초기 동네에는 대타 설 사람이 거의 없다. 크기 중~대.

### F15 안심 문답
- **무엇**: 어르신이 수락 전에 "그 사람 누구여?", 활동 중·후에 "이래도 되는겨?"를 말로 묻는다. AI는 우리 기록과 규칙 안에서만 답하고, 어르신의 당부는 봉사자에게 전할 메모로 만든다.
- **장면**: "이 사람 믿을 만혀? 우리 동네 사람이여?" → "이영수 님은 성수동에서 열두 번 도왔고 신분증 확인과 안전 교육을 마쳤어요. 범죄경력 확인서는 내지 않았어요." / "올 때 신발 벗고 들어오라 혀. 크게 말혀야 혀." → 전달 메모 → "이 말 전하고 수락". (활동 중) "통장 좀 보자는디 줘도 되는겨?" → "안 돼요…" + 신고 초안.
- **LLM이 하는 일**: 질문당 1번, 메모 1번. 질문 가르기(사람 질문·규칙 질문·당부·위급) → 코드가 준 사실 묶음 안에서만 답 → 당부 다듬기.
- **필요한 이유**: 낯선 사람이 집에 오는 서비스에서 수락을 막는 것은 불안. 금전 피해는 서비스가 한 번에 무너질 사고인데 받는 쪽이 물어볼 곳이 없다.
- **약점**: 물어보기·F09·F05와 겹친다(규칙 질문 쪽은 F05의 받는 쪽 거울). 솔직한 답("확인서 없음")이 수락률을 내릴 수도 있다. 크기 중.

### F16 단체 봉사 받기
- **무엇**: 회사·학교·교회가 "토요일 오전 12명"이라고 하면 담당자 화면에서 가구별 가벼운 일·2인 1조·조별 안내문까지 하루치를 짜고 한 번에 승인한다.
- **장면**: "23일 토요일 오전에 ○○회사에서 열두 명 온대요." → 6가구 × 2인 1조 표. "전등 갈기는 위험 작업이라 뺐어요", "인증된 조장이 2명뿐 → 4가구로 줄인 안". "박할머니 댁은 여자 조로." → "4가구 보내기".
- **LLM이 하는 일**: 행사당 3~4번. 날짜·인원 뽑기 → 어르신별로 그날 2명이 할 가벼운 일 뽑고 금지 작업 거르기 → 조 편성과 안내문 → 말로 고치기.
- **필요한 이유**: 지금은 공고 1개에 요청 1건이라 여러 명이 한꺼번에 오는 공급을 받을 수 없다. 단체 봉사는 신규 봉사자가 한 번에 들어오는 문.
- **약점**: F02와 같은 엔진. 인증 안 된 단체원이 집에 들어가는 것은 정책·법무 결정이 먼저(안 되면 성립 안 함). 단체 수요가 실제로 있는지 모른다. 크기 대.

## 팀 취향 (심사 5번 항목의 근거) — 대표가 지정: 아래 "팀원들이 직접 낸 기능 아이디어"로 판단

팀원들이 지금 직접 구상한 기능들입니다. **이것과 결이 같은 후보일수록 팀원 취향에 맞습니다.**

**1. AI 시간 연금 설계 (사용자)** — 내가 나중에 쓸 시간이 충분한지 AI가 계산하고 적립·사용 계획을 세워 준다.
- 미래 필요 시간 예측: 나와 비슷한 사람들(나이·가구 형태)의 실제 이용 기록으로 앞으로 필요할 도움 시간 예측
- 적립 목표: "지금 속도면 75세에 1년 6개월치. 월 2시간 더 모으면 3년치"
- 만약에 질문: "무릎 수술하면?" → 필요한 도움과 시간 계산(예: 약 26시간)
- 돌봄 플랜: 쓸 때가 오면 기간별 도움 계획을 짜서 공고로 한 번에 올리고, 부족하면 가족 선물 요청

**2. 시간 은행 재정 추계 (운영자)** — 지금 모은 사람들이 나중에 쓸 때 도와줄 사람이 충분한지 AI가 예측.
- 미래 수급 예측: 회원 나이 분포와 가입·이탈 추세로 연도·동네별 수요와 공급 예측(예: 2035년 희망동 수요가 공급의 1.8배)
- AI 리포트: 위험한 곳과 이유를 매달 요약 / 정책 시뮬레이션: "20대 가입이 매달 30명 늘면?" → 전후 비교 / 대응 실행: 부족한 동네·시간대 모집 문구 초안
- 숫자 계산과 예측은 코드, AI는 질문 해석·결과 설명·계획과 문구 작성

**3. 단체 봉사 (담당자·사용자)** — 마을회관 같은 기관이 공고를 올리면 교회·동호회 같은 단체가 대표자를 통해 함께 신청.
- 단체는 신청 단위일 뿐, 시간은 참여한 개인 계정에 적립. 미가입 참가자는 적립 없이 참여. 받는 쪽 차감 없음
- 담당자가 당일 출석 확인·완료 확정. 운영자가 단체 등록 승인. 종교·영리·정치 권유 금지

**4. 특보 대응 (담당자·사용자)** — 기상 특보(폭염경보 등)가 발효되면 담당자에게 알리고, AI가 안부 확인 공고 초안을 만들고, 담당자가 승인하면 도우미들이 어르신별 슬롯을 나눠 수행.
- 도우미는 "응답 있음 / 응답 없음 / 이상 있음"만 입력, 판단은 담당자(재연락·방문·보호자 연락·119)
- 운영자가 "대상 12명 중 확인 9명" 현황을 보고, 부족하면 AI가 모집 문구 초안

**팀원 프로토타입에 들어 있는 화면 이름(참고)**: AI 시간 플래너, 시간 플래너, 통장에 물어보기, 시간 통장 리포트, 시간 상속 설계, 가족 시간 통장, 놓친 혜택 찾기, 서류 작성 도우미, 내 정기 요청, 대신 봉사 요청, 사진 인증 내역, 봉사 인증 항목, 기관 소식 올리기

**여기서 읽히는 팀원 취향**: 시간 통장을 "연금·재정"처럼 **계산하고 예측하고 계획하는** 기능 / "만약에" 질문과 시뮬레이션 / **쓸 때 계획을 짜서 공고로 한 번에 올리기** / 운영자의 미래 수급 예측과 정책 시뮬레이션 / **기관·단체 단위**의 일(단체 봉사, 특보 때 어르신 여러 명 안부 확인) / 담당자가 승인하고 사람이 판단하는 구조 / 숫자는 코드, AI는 해석·설명·계획·문구.

- 부가: 효도 요청, 내 정기 요청(AI 조정 제안), 서류 도우미(신청서·고지서를 찍으면 칸마다 쓰는 법), 혜택 찾기, 약정형 봉사 적금, 묶음 추천(같은 날 같은 동네 요청 2건), 사진 인증(영수증 정리·고지서 요약·따라 하기 카드 등), 월간 리포트, 가족 시간 통장, 시간 상속 설계, 도움 받기/봉사하기 모드별 화면
- **여기서 더 읽히는 팀원 취향**: "모으기(약정·루틴)"와 "쓰기(플래너·정기 요청)"를 **금융 상품처럼 설계·약정·리뷰**하는 것 / AI가 **인터뷰 → 설계 카드 → 폼 → 등록**으로 이어 주는 흐름 / **정기(반복) 요청과 루틴** / 가족 단위(효도 요청·가족 통장·상속) / **사진을 찍어 AI가 읽는** 기능(서류·영수증·고지서) / AI가 함수 호출로 근거를 보여 주는 통장 비서 / 진행 막대·그래프·타임라인 같은 눈에 보이는 계획.
