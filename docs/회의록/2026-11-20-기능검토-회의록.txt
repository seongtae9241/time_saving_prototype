 되돌봄 서비스 기능 검토 회의록
========================================================================
회의 일자 : 2026-11-20 (화면 시연 검토 회의)
참고 회의 : 2026-11-16 서비스 기능 개선 통합 회의
주요 안건 : 다이렉트 요청·시간 지급 / 사용자 홈·공고 / 캘린더·인증 /
            기관 담당자 화면 / 운영자 화면 / 카테고리 건의 / 업무 분담
------------------------------------------------------------------------


[1] 다이렉트 요청과 시간 지급
------------------------------------------------------------------------
- 공고를 여러 사람에게 보이지 않고, 특정 사람(단골 등)에게 바로 부탁하는
  "다이렉트 요청" 흐름을 추가한다. 기존 공고 흐름은 그대로 유지한다.
- 다이렉트 요청도 공고와 같은 순서로 진행한다.
  수락 -> 봉사 진행 -> 완료 확인 -> 시간 지급
- 시간은 수락할 때가 아니라 "봉사가 끝난 뒤" 지급한다.
- 채팅에서 시간을 더 얹어 주는 "추가 지급"을 둔다. (결제 팁 같은 개념)
- 완료 후 분쟁에 대비해 신고 기능이 필요하다.
  지급 후 일정 기간은 신고할 수 있게 열어 둔다.


[2] 사용자 홈 개선
------------------------------------------------------------------------
- "추천 이웃" 영역을 탭 2개로 나눈다.
    * 추천             : AI 추천 (거리 + 카테고리 일치도 + 단골 여부 합산)
    * 자주 함께한 이웃 : 한 번이라도 함께했던 사람 목록
- 매칭 이력이 없는 신규 사용자는 "추천" 탭이 기본으로 열린다.
- 카테고리 일치도를 매번 지난 공고를 훑어 계산하지 않는다.
  마이페이지에 "주로 받는 도움 항목"을 설정으로 저장하고 그것을 기준으로 한다.
  (봉사자 쪽 "할 수 있는 도움"과 대칭)
  공고 올릴 때 쓴 카테고리를 자동으로 반영해 설정이 점차 채워지게 한다.
- 그 아래에 "기관 프로그램(행사)" 영역을 둔다.
  눌렀을 때 외부 사이트 링크 이동만 지원한다.
  기관 담당자가 직접 등록할 수 있다. (외부에서 가져오는 것 + 담당자 등록)


[3] 공고 올리기
------------------------------------------------------------------------
- "가족 선물하기(대신 올리기)"를 별도 메뉴로 두지 않고 공고 올리기에 흡수한다.
- "누구를 도와주나"는 이름을 받지 않고 정보 필드로 둔다.
    * 성별, 나이대
    * 상세 내용 (불편한 점, 휠체어 필요 여부 등)
- 시간은 항상 "공고 작성자" 통장에서 차감한다.
  (가족 계정과 연결하지 않음 -> 누구 시간이 빠지는지 헷갈리지 않게)
- 시간을 직접 주는 "시간 선물"은 시간 통장 쪽 기능으로 따로 둔다.
- 정확한 주소는 공고에 노출하지 않고 동네 단위까지만 보여 준다.
  매칭이 확정되면 채팅으로 상세 주소를 전달한다.
- 지난 공고를 불러와 수정한 뒤 다시 올릴 수 있게 한다.
- 카테고리 선택 옆에 "+" 버튼을 두어 카테고리 건의를 받는다. ([8] 참고)


[4] 시간 통장 / 생애 플랜 / 플래너 / 캘린더
------------------------------------------------------------------------
- 시간 통장, 생애 플랜, 플래너는 봉사자와 수혜자가 공통으로 쓴다.
- 캘린더는 봉사하기/도움받기 모드를 나누지 않고 하나로 합친다.
    * 봉사하는 일정 : 빨간색
    * 받는 일정     : 파란색
    * 섞인 날       : 주황색
  날짜를 누르면 항목별로 색이 구분되어 보인다.
- 봉사자 홈과 수혜자 홈은 거의 같다. 봉사자 홈에만 봉사 확인서 진입점이 있다.
- 봉사 확인서가 홈에 있는 위치가 어색하다.
  "더보기 -> 내역 -> 확인서" 순서로 열리게 옮긴다.


[5] 인증과 교육
------------------------------------------------------------------------
- 회원가입은 인증 없이 된다.
- 봉사하기 / 도움받기를 처음 할 때 신분증 인증과 필수 교육을 거쳐야 한다.
  교육 미수료자는 막는다. (봉사자, 수혜자 모두)
- 수혜자의 신고 내역은 "내가 신고한 것"으로 보여 준다.


[6] 기관 담당자 화면
------------------------------------------------------------------------
(1) 기관 공고(단체 봉사)
  - 기관이 "봉사자 N명 필요" 공고를 올리면 봉사자는 개인으로 신청하거나
    이웃을 초대해 단체로 신청할 수 있다.
  - 사용자 내역의 "기관에게 요청" 용어가 내가 한 신청인지 받은 요청인지
    헷갈린다. -> 용어 수정
  - 요청 관리에서 확정된 건과 진행 중인 건을 색으로 확실히 구분한다.

(2) 관리 대상과 대신 요청(위임)
  - 관리 대상자는 시스템 회원이 아니라 "기관의 데이터"다.
  - 관리 대상 정보는 기본으로 보이지만, 대신 요청 / 수락은
    보호자 동의 또는 서면 위임장을 받은 사람만 할 수 있다.
  - 위임받은 대상자만 대신 요청 화면에 나오고, 요청은 공고 형태로 올라간다.
  - 담당자가 공고를 "직접 쓰는" 기능도 추가한다. (AI 정리 외에)
  - 신청이 들어오면 승인/거부 버튼이 아니라 일반 사용자와 같은 방식으로 간다.
    여러 신청자와 채팅으로 이야기한 뒤 한 명을 최종 확정한다.
  - "메시지"라는 이름은 쓰지 않고 "채팅"으로 통일한다.
    (내가 요청하지 않아도 상대 메시지가 와야 하므로 채팅 구조가 맞음)

(3) 담당자 그룹핑과 인수인계
  - 지금은 모든 담당자가 같은 대상자를 본다.
    담당자별로 "내 담당 대상자"를 묶는 그룹핑이 필요하다.
  - 기본 화면은 내 담당 대상자만 보여 주고, 기관 전체 대상자는 검색해서 본다.
  - 담당자가 바뀔 때를 위한 담당자 간 인수인계(위임)는 유지한다.

(4) 돌봄 편성표
  - 같은 시간에 여러 대상자 일정이 겹치는 경우를 놓치고 있었다.
  - "전체 달력(월)"을 기본으로 하고, 날짜를 누르면 화면 전환 없이
    "옆 패널"에 그날 일정이 펼쳐지게 한다. (아래로 내려가거나 페이지 이동 X)
  - 사람별 보기는 전체 리스트를 없애고, 이름으로 검색해 한 사람 일정만 본다.
  - 주/일 보기 등 나머지 보기는 꼭 필요하지 않다.
  - 한 시간대에 일정이 많을 때의 표현 방식은 디자인에서 더 고민한다.

(5) 공공서비스 연계
  - 처음 구상(대상자가 AI에게 묻고 담당자에게 넘김)은 대상자가 회원이 아니라서
    맞지 않는다.
  - 담당자가 대상자의 비식별 정보(연령대, 지역 등)로
    "이 분이 받을 수 있는 공공서비스"를 조회하는 기능으로 바꾼다.
  - 신청은 담당자가 수동으로 하거나 대상자에게 안내한다.
  - 이름, 주민번호 등 개인정보는 AI에 보내지 않는다.

(6) 특보
  - 기상특보는 API로 가져온다. (다른 종류 특보는 아직 미정)
  - 운영자가 담당자에게 따로 보내는 "운영자 안내"는 없앤다.
    (담당자가 현장 판단을 더 잘함 -> AI 분석으로 합침)
  - 한 단계 더 나아가 AI가 특보에 노출된 독거노인 등
    "확인이 필요한 대상자 명단"까지 보여 준다.
  - 안부 확인 기록에 메모를 남길 수 있게 한다.
    여러 담당자가 함께 보는 포스트잇처럼 쓴다. (예: 연락 안 됨, 방문함)

(7) 리포트
  - 공고 빈도, 앱 활동 빈도, 일지 내용을 AI가 분석해
    "먼저 안부를 물어보세요" 같은 제안을 한다.
  - 실제 품질은 해 봐야 안다. 데이터가 많이 필요하다.
  - 비식별 전처리(이름·주민번호 등 제거)가 핵심이다.


[7] 운영자 화면
------------------------------------------------------------------------
(1) 대시보드
  - 총 가입자, 신규 가입자, 등록 기관 수, 월별 도움 요청 건수,
    봉사 신청 건수, 전체 공고 수, 처리할 일
  - 도움 요청이 너무 많아지면 알려 주고, 시뮬레이션으로 독려 방법을 추천한다.
    (예: 이벤트를 열면 봉사자가 얼마나 늘지)

(2) 이용 리포트
  - 봉사 유형별, 나이별(요청 / 가능 각각), 지역별, 계절별 통계
  - 수급 히트맵 : 빨강 = 부족, 파랑 = 여유. 지역별 화면은 따로 있다.
    히트맵 표현은 고민 중이었으나 현재 안이 괜찮다는 반응.

(3) 특보 알림 / 공지
  - 기관 담당자에게는 보내지 않는다. (AI 분석으로 합침)
  - 일반 사용자에게는 운영자가 쓰는 공지사항이 앱 상단 배너로 뜬다.
    공지는 AI로 써도 되고 직접 써도 된다.

(4) 승인과 처리
  - 승인 대상 : 기관 신청, 담당자 계정, 봉사자 신원 인증
  - 신고 / 문의 처리 화면
  - 신고 처리 방식 : 이용정지, 경고, 기각
  - 이용정지 시 공고 작성, 신청, 채팅 등 모든 활동이 막힌다.


[8] 카테고리 건의
------------------------------------------------------------------------
- 사용자 마이페이지 "문의하기"가 아니라 공고 올리기의 카테고리 선택 옆
  "+" 버튼으로 받는다. (문의 = 질문·답변, 건의 = 성격이 다름)
- 운영자는 승인할 때 카테고리 이미지와 아이콘을 지정한다.
  승인 / 반려 화면이 필요하다.


[9] 업무 분담
------------------------------------------------------------------------
- 기관 담당자 화면 : 특보를 제외한 전체
- 운영자 화면      : 특보를 제외한 전체
- 사용자 화면      : 두 명이 나눠서 진행, 그중 한 명이 공통 부분 담당
- 알림 / 특보      : 원래 신우님 담당 예정이었으나 연락이 없어
                     4명 분량으로 계산해 진행. 월요일에 다시 이야기해 결정.
- 액터는 사용자, 담당자, 운영자 3개. 볼륨은 4명이 완성도 있게 할 정도로 판단.

 [부록] 기관 담당자 파트 할 일 (현재 10판 프로토타입 기준)
========================================================================
 회의 결정과 지금 프로토타입이 다른 부분
------------------------------------------------------------------------
 1. 요청 상세 "메시지" -> "채팅"으로 이름 통일, 일반 사용자와 같은 채팅 방식
 2. 신청이 오면 승인/거부 대신, 여러 신청자와 채팅 후 한 명 최종 확정
 3. 대신 요청에 "직접 쓰기" 추가 (AI 정리만 있음)
 4. 대신 요청 대상은 위임받은 대상자만 표시
 5. 담당자별 "내 담당 대상자" 그룹핑 + 기관 전체 검색 (지금은 모두 같은 목록)
 6. 편성표: 전체 달력(월) 기본 + 날짜 누르면 옆 패널 상세,
    사람별은 이름 검색으로 한 사람만 (주/일 보기, 전체 사람 리스트 제거)
 7. 요청 관리: 확정 / 진행 중을 색으로 확실히 구분
 8. 공공서비스 연계: "본인이 전달한 AI 대화" 흐름 제거,
    담당자가 대상자 비식별 정보로 받을 수 있는 서비스 조회
 9. 특보: "운영자 안내" 제거, AI가 확인 필요 대상자 명단 제시
10. 안부 확인 기록에 메모(포스트잇) 남기기, 여러 담당자 공유
11. "앱 쓰는 분", "앱에서 온 요청" 등 관리 대상이 앱을 쓰는 전제 정리
    (관리 대상은 회원이 아님)
12. 기관 행사(프로그램)에 외부 링크 입력 칸

 2026-11-16 회의 결정과 다른 부분 (지난번 분석)
------------------------------------------------------------------------
13. 단골 자동 등록 문구 제거 (직접 등록만)
14. 진행 단계 이름: 확정 -> 최종 수락, 진행 중 -> 활동 중
15. 대신 최종 수락 시 "최종 수락하면 취소할 수 없어요" 안내
16. 사이드바 권한 위임을 맨 아래로
