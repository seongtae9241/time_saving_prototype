# 2차 조사 (직접 열람) — 2026-11-18

갤러리 사이트가 열리게 되어 **페이지를 직접 열고 1440 폭 사진을 찍어 눈으로 보고** 후보를 다시 골랐다.
직접 본 후보는 **부품 조각 27개**(화면으로는 22쪽: Kombai 18쪽 + Fancy UI 4쪽)이고, 작은 그림과 설명 글로만 본 참고 후보가 3개 더 있다. Mobbin·The UI Index는 페이지는 열리지만 **그림이 다른 주소에서 와서 막혀** 후보를 뽑지 못했다.

> **먼저 읽을 것**
> - 아래 후보의 색·모서리·그림자 설명은 **본 것만** 적었다. 색 값(#……)은 두 가지에서만 나온 것이다: ① Kombai가 작품 설명 글에 직접 적어 둔 값, ② Fancy UI 실제 페이지에서 브라우저로 읽은 값. 그 밖의 색은 "짙은 청록"처럼 말로만 적었다.
> - **Kombai는 멈춘 그림 1장만 봤다.** 실제로 움직이는 미리보기(`agent.kombai.com`)가 막혀 있어 마우스 올림·움직임은 못 봤다.
> - Kombai·Fancy UI의 서비스 이름(Tidewell, Hollis, Scholar 등)은 **모두 지어낸 가짜 서비스**다. Fancy UI는 스스로 "Fictional businesses"라고 적어 두었고, Kombai도 실제 회사 화면이 아니라 갤러리용으로 만든 화면이다.
> - 참고 화면 대부분이 **초록·청록 강조색**이다. 우리는 모양·배치만 가져오고 색은 시안의 강조색(코랄 `--acc #B84A2D` / 라벤더 `--acc #6252C4`)으로 바꾼다.
> - 전제는 그대로: 그림·아이콘·코드·글을 내려받아 쓰지 않는다. 패턴만 보고 인라인 SVG/CSS로 다시 그린다. 찍은 사진은 작업용 임시 폴더에만 있고 저장소에 넣지 않았다.

2. 참고 화면에 흔한 것 중 **우리 규칙에 걸려 가져오지 않는 것**: 떠 있는 동그라미 버튼(Sorrel·Northaven·Hearthway), 본문을 덮는 AI 패널, 도넛·진행 링(Feldspar·OCTA), 사진 아바타, 이모지(👋), 같은 크기 카드 격자, 사람마다 다른 아바타 색, 깜빡이는 점, 색 사이드바.
3. Kombai 그림은 멈춘 1장이라 **마우스 올림·움직임은 못 봤다.** 움직임 값은 Fancy UI에서 읽은 것(카드 0.14초, 버튼 0.15초, 화면 들어옴 0.28초)과 eat-go 코드가 근거다.
4. Fancy UI는 Geist 글꼴을 쓴다. **글꼴은 가져오지 않는다**(새 외부 리소스 금지).
5. 라벤더안은 직접 본 화면(Roster·Reedline·Tessel·OCTA)에서 **바탕·칸·사이드바까지 보라 기운**일 때 예뻤다. 우리는 크롬이 무채색이어야 하고 AI가 보라라서, 그대로 옮기면 AI 표시가 묻힌다 — 라벤더안을 고르면 AI 색을 어떻게 구분할지 먼저 정해야 한다.
6. 코랄안은 직접 본 화면 중 코랄이 주인공인 것이 **없었다**(Hearthway 적갈색, Fluenta 주황 버튼, Feldspar 코랄 점 정도). 코랄 화면의 실제 느낌은 여전히 eat-go가 가장 좋은 근거다.

## 2-F. 2차 조사에서 확인 못 한 것

1. **Mobbin(실제 서비스 화면)을 못 봤다.** `bytescale.mobbin.com`이 열리면 Work Dashboard·Kanban·Notifications·빈 상태·표·필터를 실제 서비스(Jobber, Front, Midday, Clay 등) 화면으로 볼 수 있다. 이번 후보는 전부 "갤러리용으로 만든 화면"이라 실제 서비스에서 검증된 화면이 아니다.
2. Kombai 작품의 **움직이는 미리보기**(`agent.kombai.com`)를 못 열어 마우스 올림·전환·반응형을 못 봤다.
3. The UI Index 화면, UI Garage, UI Design Daily, Component Gallery는 못 봤다. Collect UI는 열렸지만 작품이 비어 있었다(왜 비었는지 모름).
4. Kombai 갤러리 작품의 **이용 조건을 따로 적은 문구를 찾지 못했다**(약관의 일반 조항만 확인). 그래서 코드·그림은 가져오지 않고 패턴만 참고한다.
5. Kombai 작품이 사람이 그린 것인지 AI가 만든 것인지, 실제 서비스를 본뜬 것인지는 사이트에 적힌 것을 찾지 못했다(이름은 모두 실제 회사가 아니다).
6. D16(Cadence)·D28(Quillpoint)·D30(Alderbrook Grounds)과 "작은 그림으로만 본 것" 6개는 큰 그림으로 확인하지 않았다.
7. Fancy UI는 쿠키 동의 창이 왼쪽 아래를 가려 Vitals의 병상 지도, Scholar의 "다음 수업" 목록 윗부분, Relay 첫 칸 셋째 카드 아래는 못 봤다. Fancy UI 20종 중 큰 그림으로 본 것은 4종, 작게 본 것 4종(Still·Griddle·Pulse·Hearth — 모두 어두운 화면이라 후보에서 뺌), 나머지 12종은 안 열었다.
8. 국내 서비스 화면, 돌봄·봉사 분야의 **실제 업무 화면**은 이번에도 못 봤다(Hearthway가 돌봄 중개를 흉내 낸 화면 1건).
9. 코랄 강조색 위에서 빨간 배지·특보 띠가 어떻게 보이는지는 참고 화면이 없어 확인하지 못했다 — 시안에서 직접 찍어 봐야 한다.

## 4. 화려함을 써도 되는 곳 / 쓰면 안 되는 곳

**써도 되는 곳** (규칙을 안 깸)
- 홈 맨 위 인사 한 줄 영역(낮게), 숫자 카드의 아이콘 타일, 진행 막대, 빈 상태의 작은 선 그림, 사람 아바타, 확인 창 머리 아이콘, 버튼·칩·카드의 마우스 반응, 화면 들어올 때 한 번의 움직임, 리포트의 그래프.

**쓰면 안 되는 곳**
- 표와 목록의 줄(처리할 일, 관리 대상 목록), 긴 글(일지·메모), 편성표 달력 칸 안, 위험·특보 띠(이미 빨강 — 더 꾸미면 눈이 피곤), 폼 입력칸.

**색 원칙** — 꾸밈에 쓰는 색은 **강조색 한 가지와 그 옅은 단계**만. 파랑·초록·빨강·호박·보라는 뜻이 있을 때만.

### (가) 조금만 화려하게 — "지금 틀 그대로, 살만 붙이기"

| 화면 | 부품 | 쓰는 패턴 |
|---|---|---|
| 전체 | 카드 | 둥글기 12 → 16px, 옅은 그림자 한 겹. 누를 수 있는 카드만 마우스 올리면 2px 떠오름 (eat-go `.surface-card`) |

| 홈 | 접힌 "이번 주 현황" | 펼치면 숫자 3개에 색 아이콘 타일(뜻 색) — 후보 1, eat-go `.metric-card` |

- 규칙과 부딪히는 곳: 거의 없음.
- 코랄: 지금 시안과 가장 가까움. 주 버튼·선택 메뉴·숫자 강조만 코랄. 위험 빨강과 헷갈리지 않게 **특보 띠 근처에는 코랄을 쓰지 않음**.
- 라벤더: 차분하고 눈이 편함. 하지만 **AI 보라와 겹침** → AI 표시는 색이 아니라 "반짝 아이콘 + AI 안내 글자"로 구분하거나, AI 색을 더 진한 남보라로 옮겨야 함.
- 예상 반응: 디자이너가 "여전히 심심하다"고 할 가능성이 큼.

### (나) eat-go 수준 — "eat-go의 여섯 가지를 규칙 안에서 옮기기" (추천)

| 화면 | 부품 | 쓰는 패턴 |
|---|---|---|
| 홈 | 맨 위 인사 띠 | 강조색 아주 옅은 그라데이션 띠(높이 72~88px, 둥글기 20px): 왼쪽 인사 + 날짜, 오른쪽에 알약 숫자 3개(처리할 일·빈칸·새 일지) — eat-go 히어로. **특보가 있으면 특보 띠가 인사 띠보다 위** |
| 홈 | 처리할 일 표 | 표는 그대로(꾸미지 않음). 응답 기한만 알약 배지로 |
| 홈 | 먼저 살펴볼 분 | 순위 숫자 대신 첫 글자 아바타(강조색 옅은 바탕) + 줄이 차례로 들어옴 — eat-go `.perf-row` (맥박 테두리는 빼기: 빨강 남발) |
| 홈 | 이번 주 현황(접힘 유지) | 펼치면 벤토 배치: 큰 칸 1개(완료 7/9 + 진행 막대) + 작은 칸 3개(아이콘 타일 + 숫자) — 후보 2 + eat-go `.metric-card` |
| 관리 대상 | 상세 머리 | 아바타에 강조색 한 겹 링 + 태그 칩 + 주 버튼 1개 — 후보 16, eat-go 프로필(무지개 링은 빼기) |
| 편성표 | 달력 | 달력 칸은 그대로. 위쪽 기간 고르기를 조각 버튼으로, 오늘 날짜만 강조색 알약 |
| 요청 보드 | 칸·카드 | 칸 머리에 뜻 색 점 + 개수 알약, 카드 아래 줄에 봉사자 아바타 + 날짜, 마우스 올리면 떠오름 — 후보 11 |
| 리포트 | 그래프 | 선이 그려지는 움직임의 선 그래프(축·단위·기간 표시), 위쪽만 둥근 막대 — eat-go 대시보드·통계, 후보 19 |
| 서랍·확인 창 | 머리 | 색 아이콘 타일 + 제목, 살짝 커지며 등장 + 뒤 배경 옅은 흐림 — eat-go 모달, 후보 24 |
| AI 도우미 | 옆 칸 | 제안 칩(알약) + 답 + 근거 줄, 보라 옅은 바탕 — 후보 25 |
| 머리줄 | | 반투명 흰색 + 뒤 흐림(스크롤할 때만 선 보임) — eat-go 머리줄 |

- 규칙과 부딪히는 곳과 풀이
  - "중요한 것 먼저": 인사 띠가 처리할 일을 아래로 밀어냄 → 띠 높이를 90px 아래로, 띠 안에 **처리할 일 숫자**를 넣어 띠 자체가 요약이 되게.
  - "같은 크기 격자 금지": 숫자 카드는 벤토(큰 칸 1 + 작은 칸 3)로.
  - "첫 화면 그래프 금지": 홈에는 진행 막대까지만. 선 그래프는 리포트에서만.
  - "원 그래프 금지": 도넛·링은 쓰지 않고 막대로.
  - "떠 있는 요소 금지": 토스트 대신 화면 위쪽 띠(지금 방식 유지).
- 코랄: eat-go와 같은 계열이라 디자이너가 원하는 느낌에 가장 가까움. 인사 띠는 코랄 5% 정도의 아주 옅은 색. 후보 15(주황 + 남보라)처럼 코랄과 AI 보라가 잘 어울림. 주의: 코랄 옅은 바탕과 위험 연분홍 바탕(특보 띠)이 비슷해 보임 → 인사 띠에는 테두리 없이, 특보 띠에는 빨간 선 아이콘 + 테두리로 구분.
- 라벤더: 어르신 돌봄에 어울리는 차분한 인상, 눈 피로 적음. 주의: 인사 띠·아바타·AI 패널이 모두 보라 계열이 되어 **AI 표시가 묻힘** → AI는 더 진한 남보라 + 아이콘으로만 구분하거나 AI 패널에 선 테두리를 줌. 주 버튼의 흰 글씨 대비(4.5:1 이상)도 확인.

## 6. 확인 못 한 것 (1차 조사 때)

1. **후보 30개의 실제 화면을 하나도 보지 못했다.** 색·모양·움직임 설명은 검색 요약(제목·태그·일부 색 코드)에서 나온 것뿐이다. 디자이너가 주소를 직접 열어 확인해야 한다.
2. 12개 사이트 모두 직접 열람 실패: awwwards.com, cssdesignawards.com, siteinspire.com, wwit.design, uibowl.io, dribbble.com, behance.net, pinterest.com, designspiration.com, gdweb.co.kr, dbcut.com, notefolio.net. 이 작업 환경의 네트워크 설정에서 이 주소들을 허용해야 다시 조사할 수 있다. (로그인·봇 차단을 우회하지 않았다.)
3. **DBCUT에서는 작품을 하나도 찾지 못했다.** 검색에 작품 페이지가 잡히지 않는다.
4. Pinterest·Designspiration은 남의 작품을 "저장"한 페이지라 **원작자와 원본 주소를 확인하지 못했다.** 참고하려면 원본을 먼저 찾아야 한다.
5. 검색 결과 주소가 지금도 열리는지(삭제·비공개 여부), 각 작품의 이용 조건은 확인하지 못했다. Dribbble·Behance 작품은 저작권이 작가에게 있으므로 패턴 참고까지만 한다. Creative Tim·LUNO 같은 판매용 템플릿은 코드를 가져다 쓰지 않는다.
6. 후보가 Dribbble에 조금 몰렸다(9/30). 돌봄·봉사 주제의 PC 업무 화면은 Dribbble·Behance 밖에서는 거의 검색되지 않았다.
7. eat-go는 코드만 읽었고 화면을 띄워 보지 않았다(실행·빌드 금지). 움직임의 실제 느낌은 코드의 시간·곡선 값으로 짐작한 것이다.
8. 화면 규칙 문서는 본문 최대 폭을 1080px이라고 하는데, 지금 시안(PC-3)의 코드는 1240px이다. 어느 쪽이 맞는지 팀 확인이 필요하다.
9. "진행 링이 원 그래프 금지에 들어가는지", "아주 옅은 따뜻한 바탕이 무채색 크롬 규칙에 맞는지"는 팀이 정해야 한다.
