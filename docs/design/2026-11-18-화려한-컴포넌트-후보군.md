# 화려한 컴포넌트 후보군 (기관 담당자 PC 화면)

- 만든 날: 2026-11-18
- 목적: 지금 시안(proto-2026-11-17-기관담당자-PC-3)이 "너무 차분하다"는 디자이너 의견에 맞춰, eat-go 수준으로 화려하게 만들 때 조각으로 옮겨 쓸 디자인 후보를 모은다.
- 전제: 남의 작품은 **패턴(배치·구성 방식)만 참고**하고 우리 것으로 다시 그린다. 그림·일러스트·아이콘 파일은 내려받지 않는다.

> **먼저 읽을 것 — 이 문서의 한계**
> 이번 조사 환경은 바깥 사이트를 직접 여는 것이 막혀 있었다(12개 사이트 모두 열람 실패, 5번 절 참고).
> 그래서 **후보 30개 전부 "검색 결과 요약만 봄"이고, 실제 화면을 눈으로 본 것은 0개**다.
> 주소는 모두 검색 결과에 실제로 나온 것만 적었다(지어낸 주소 없음). 하지만 "어떤 색·모양인지"는 제목·태그·요약 글로 아는 범위까지만 적었고, 모르는 것은 "화면 미확인"이라고 적었다.
> 반대로 **1번 절(eat-go 분석)과 우리 시안 비교는 코드와 사진을 직접 읽고 쓴 것**이라 믿어도 된다. 추천 3안도 eat-go에서 확인한 패턴을 뼈대로 잡았다.
> 디자이너가 후보 주소를 직접 열어 보고 골라야 한다.

## 1. eat-go 디자인 분석 (코드를 직접 읽음)

읽은 파일: `assets/css/tokens.css`, `common/head-assets.jsp`, `main.jsp`, `store-detail.jsp`, `ceo/home.jsp`, `ceo/statistics.jsp`, `ceo/sales.jsp`, `ceo/sidebar.jsp`, `ceo/badge.jsp`, `admin/header.jsp`, `admin/dashboard.jsp`.

### 1-1. eat-go의 "화려함"은 무엇으로 이루어져 있나

| 구분 | eat-go에 있는 것 | 어디에 |
|---|---|---|

| 색 띠 상자 | 연한 코랄 바탕 알림 띠 + 흰 동그라미 아이콘 + 코랄 버튼. 연한 코랄·연한 초록 바탕의 성과 상자 | `ceo/home.jsp` |

| 칩·배지 | 알약 모양 카테고리 칩(선택되면 코랄로 채움), 상태 배지(연한 바탕 + 진한 글자), 기간 고르기(일·주·월·년 조각 버튼, 마우스만 올려도 미리 보기) | `main.jsp`, 대시보드 |

| 입력칸 | 포커스 때 코랄 테두리 + 3px 연한 코랄 띠 | `admin/header.jsp` |
| 어두운 띠 | 화면 아래 검은 큰 안내 띠(흰 글자) | `main.jsp` |

| 이모지 | 사장님 홈 빠른 메뉴에 이모지 아이콘 8개 | `ceo/home.jsp` |

정리하면 eat-go의 화려함은 "특별한 그림"이 아니라 **① 따뜻한 색 바탕 ② 옅은 그라데이션 히어로 ③ 둥글고 떠오르는 카드 ④ 색 아이콘 타일이 붙은 숫자 카드 ⑤ 움직이는 손그림 그래프 ⑥ 들어올 때 차례로 나타나는 움직임** 여섯 가지가 겹친 것이다. 그래프도 라이브러리 없이 SVG로 그렸기 때문에 **우리 규칙(새 라이브러리 금지) 안에서 거의 다 다시 그릴 수 있다.**

### 1-2. 지금 시간 적금 시안의 모습 (사진 4장 + 코드 확인)

- 바탕이 차가운 회색(`#F4F5F7`), 글꼴 IBM Plex Sans KR, 카드는 흰 바탕 + 1px 선, 그림자 거의 없음, 둥글기 6~14px.
- 색은 뜻에만(요청 파랑·확정 초록·위험 빨강·주의 호박·AI 보라) — 규칙 그대로.
- 홈은 표 + 순위 목록 + 일정 목록 + 접힌 줄 3개. 숫자 카드·인사 영역·그림 없음.
- 움직임은 3개뿐(깜빡임, 오른쪽에서 들어옴, 아래에서 올라옴). 그라데이션 2곳.

### 1-3. "eat-go에는 있고 우리 시안에는 없는 것" 목록

| # | 없는 것 | 우리 규칙과 부딪히나 |
|---|---|---|
| 1 | 인사·요약 히어로(옅은 그라데이션 큰 상자) | 안 부딪힘. 단 "중요한 것 먼저"라서 **작게, 처리할 일 표 위에 한 줄~두 줄 높이**로 |
| 2 | 색 아이콘 타일이 붙은 숫자 카드 | 색을 뜻(파랑·초록·빨강·호박)에 맞추면 괜찮음. 같은 크기 4개 격자는 "찍어 낸 격자 금지"와 부딪힘 → 크기 차이를 줘야 함 |
| 3 | 큰 숫자(22~28px 굵게) | "쓸데없이 큰 것 금지"와 살짝 부딪힘 → 화면당 1~3개만 |
| 4 | 마우스 올리면 떠오르는 카드 | 안 부딪힘(누를 수 있는 카드에만) |
| 5 | 들어올 때 차례로 나타나는 움직임, 반짝이는 뼈대 | 안 부딪힘. 매일 8시간 쓰는 화면이라 **처음 한 번, 0.3초 안쪽**으로. 움직임 줄이기 설정 지키기 |
| 6 | 움직이는 선 그래프·도넛 | **첫 화면 그래프 금지, 원 그래프 금지**와 부딪힘 → 리포트·접힌 구역에서만, 도넛은 쓰지 않음 |
| 7 | 작은 진행 막대 + % | 안 부딪힘(무엇을 센 것인지 한 줄 필요) |
| 8 | 유리 효과 머리줄(반투명 + 흐림) | 안 부딪힘. 글씨 대비만 확인 |
| 9 | 따뜻한 회갈색 바탕 | "화면 크롬은 무채색"과 살짝 부딪힘 → 팀 결정 필요(아주 옅은 따뜻한 회색은 무채색으로 볼 수 있는지) |
| 10 | 무지개 링 아바타·그라데이션 표지 프로필 | 색이 뜻 없이 쓰여 부딪힘 → 링은 한 가지 색(강조색)으로만 |
| 11 | 알약 칩(선택 시 색 채움), 조각 버튼 | 안 부딪힘 |
| 12 | 옆에서 들어오는 토스트 | **"떠 있는 요소가 글을 덮지 않기"와 부딪힘** → 위쪽 띠로 대신 |
| 13 | Poppins 숫자 글꼴 | **새 외부 리소스 금지와 부딪힘** → 쓰지 않음. 지금 글꼴 굵기·크기로 대신 |
| 14 | 이모지 아이콘 | **이모지 금지와 부딪힘** → 선 아이콘 + 색 타일로 대신 |
| 15 | 사진(표지·상품) | 우리는 실명·사진을 저장하지 않음 → 쓰지 않음. 이름 첫 글자 아바타로 대신 |
| 16 | 어두운 큰 안내 띠 | 업무 화면에는 과함 → 쓰지 않음 |

## 3. 후보 표 (30개, 부품별)

읽는 법
- **확인**: 전부 "검색 요약만"(실제 화면 미확인). 반복을 줄이려고 표 머리에만 적는다.
- **요약으로 아는 것**: 검색 결과의 제목·태그·설명에서 확인된 사실만.
- **가져올 것**: 모두 **패턴(배치·구성 방식)**이지 그림 자체가 아니다.
- **부딪힘**: 우리 화면 규칙(`timesavings-org-ui`)과 부딪히는 곳.

## 4. 화려함을 써도 되는 곳 / 쓰면 안 되는 곳

**써도 되는 곳** (규칙을 안 깸)
- 홈 맨 위 인사 한 줄 영역(낮게), 숫자 카드의 아이콘 타일, 진행 막대, 빈 상태의 작은 선 그림, 사람 아바타, 확인 창 머리 아이콘, 버튼·칩·카드의 마우스 반응, 화면 들어올 때 한 번의 움직임, 리포트의 그래프.

**쓰면 안 되는 곳**
- 표와 목록의 줄(처리할 일, 관리 대상 목록), 긴 글(일지·메모), 편성표 달력 칸 안, 위험·특보 띠(이미 빨강 — 더 꾸미면 눈이 피곤), 폼 입력칸.

**색 원칙** — 꾸밈에 쓰는 색은 **강조색 한 가지와 그 옅은 단계**만. 파랑·초록·빨강·호박·보라는 뜻이 있을 때만.

- 규칙과 부딪히는 곳: 거의 없음.
- 코랄: 지금 시안과 가장 가까움. 주 버튼·선택 메뉴·숫자 강조만 코랄. 위험 빨강과 헷갈리지 않게 **특보 띠 근처에는 코랄을 쓰지 않음**.
- 라벤더: 차분하고 눈이 편함. 하지만 **AI 보라와 겹침** → AI 표시는 색이 아니라 "반짝 아이콘 + AI 안내 글자"로 구분하거나, AI 색을 더 진한 남보라로 옮겨야 함.
- 예상 반응: 디자이너가 "여전히 심심하다"고 할 가능성이 큼.

## 6. 확인 못 한 것

1. **후보 30개의 실제 화면을 하나도 보지 못했다.** 색·모양·움직임 설명은 검색 요약(제목·태그·일부 색 코드)에서 나온 것뿐이다. 디자이너가 주소를 직접 열어 확인해야 한다.
2. 12개 사이트 모두 직접 열람 실패: awwwards.com, cssdesignawards.com, siteinspire.com, wwit.design, uibowl.io, dribbble.com, behance.net, pinterest.com, designspiration.com, gdweb.co.kr, dbcut.com, notefolio.net. 이 작업 환경의 네트워크 설정에서 이 주소들을 허용해야 다시 조사할 수 있다. (로그인·봇 차단을 우회하지 않았다.)
3. **DBCUT에서는 작품을 하나도 찾지 못했다.** 검색에 작품 페이지가 잡히지 않는다.
4. Pinterest·Designspiration은 남의 작품을 "저장"한 페이지라 **원작자와 원본 주소를 확인하지 못했다.** 참고하려면 원본을 먼저 찾아야 한다.
5. 검색 결과 주소가 지금도 열리는지(삭제·비공개 여부), 각 작품의 이용 조건은 확인하지 못했다. Dribbble·Behance 작품은 저작권이 작가에게 있으므로 패턴 참고까지만 한다. Creative Tim·LUNO 같은 판매용 템플릿은 코드를 가져다 쓰지 않는다.
6. 후보가 Dribbble에 조금 몰렸다(9/30). 돌봄·봉사 주제의 PC 업무 화면은 Dribbble·Behance 밖에서는 거의 검색되지 않았다.
7. eat-go는 코드만 읽었고 화면을 띄워 보지 않았다(실행·빌드 금지). 움직임의 실제 느낌은 코드의 시간·곡선 값으로 짐작한 것이다.
8. 화면 규칙 문서는 본문 최대 폭을 1080px이라고 하는데, 지금 시안(PC-3)의 코드는 1240px이다. 어느 쪽이 맞는지 팀 확인이 필요하다.
9. "진행 링이 원 그래프 금지에 들어가는지", "아주 옅은 따뜻한 바탕이 무채색 크롬 규칙에 맞는지"는 팀이 정해야 한다.
