| 서비스 규칙 ① 시간 | 1시간 활동 = 1시간 적립. 가중치·난이도 등급은 쓰지 않는다(2026-11-19 팀 결정). 앱 코드에서는 아직 제거 전. |
| 서비스 규칙 ② 관리 대상 | 관리 대상은 별칭으로만 저장한다. 실명·주소·연락처는 저장하지 않는다(elders 표에 그런 칸이 없음). 별칭·주의사항·메모·관리 대상 이슈에 연락처·상세 주소가 보이면 서버가 400 PII_NOT_ALLOWED 로 막는다. 봉사자에게는 별칭도 가려서 보인다. 병명은 적지 않는다. |
| 서비스 규칙 ③ 결정은 사람이 | 수락·거부·거절·이관·지원 종료·처리 상태·변화 큰 사례 표시는 모두 담당자가 직접 누른다. AI 추천이나 편성 추천은 아무것도 보내거나 만들지 않는다(sent:false). 요청 관리 보드에서도 끌어 옮기기는 없다. |
| 서비스 규칙 ④ 진단 안 함 | 변화 리포트·확인 권장 표시는 "먼저 안부를 물어보라"는 안내일 뿐 건강 진단·판단이 아니다. 응답의 notice 문구로 화면에 알린다. |
| 서비스 규칙 ⑤ 숫자는 코드가 | 횟수·순서·점수·적립 시간·후보는 코드가 계산한다. AI는 설명 문장(요약·추천 이유·메모 정리)만 만든다. AI 키가 없으면 규칙으로 만든 문장을 준다(source=rule). |
| 응답 형식 | 성공: 본문 JSON 을 그대로 준다(감싸는 {success, data} 없음). 실패: HTTP 상태 + {"error":"문장", "code":"코드"}. 코드는 「에러 코드」 시트. |
| 인증 | 토큰 인증. 로그인하면 무작위 토큰을 auth_token 표에 저장하고(로그인 유지 30일 · 아니면 1일), 요청마다 Authorization: Bearer {토큰} 으로 보낸다. 프론트는 localStorage(ts-token)에 둔다. JWT·refresh 토큰은 쓰지 않는다. |
| 역할 검사 | AuthInterceptor 가 /api/org/** 는 ORG, /api/admin/** 는 ADMIN 만 지나가게 한다. 프론트는 App.jsx 의 Guard 가 화면 주소별로 역할을 본다. 담당자 API 안에서는 "내가 담당하는 대상인가"(elders.manager_id) 또는 "우리 기관 것인가"(org_id)를 한 번 더 확인한다. |
| 로그인 사용자 | 담당자 id 는 요청에 보내지 않는다. 서버가 토큰으로 찾은 사용자를 @CurrentUser User 로 받는다. SQL 의 manager_id=? · user_id=? 자리가 그 값이다. |
| 검증 | 요청 본문은 record(예: ElderBody)로 받고, 값 검사는 컨트롤러·서비스에서 직접 한 뒤 ApiException(상태, 코드, 문장)을 던진다. @Valid 는 거의 쓰지 않는다. |
| SQL 칸 | JPA(Spring Data) 를 쓴다. SQL 칸에는 Repository 메서드 이름과 그에 해당하는 SQL 을 적었다. 표·칸 이름은 엔티티 기준(자바 이름을 밑줄 표기로 바꾼 것)이다. "(변경 감지)"는 @Transactional 안에서 엔티티 값을 바꾸면 JPA 가 UPDATE 를 보내는 것을 뜻한다. findAll() 로 모두 읽은 뒤 자바에서 거르는 곳이 많다(자료가 많아지면 조건 조회로 바꿔야 함). |
| 트랜잭션 | OrgController · OrgBlockController 는 클래스에 @Transactional. OrgScheduleController 는 일괄 등록이 칸마다 따로 저장돼야 해서 붙이지 않았다. |
