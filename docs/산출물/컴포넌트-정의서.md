## 1. 개요

### 1-2. 상태 관리
전역 상태 라이브러리는 없고, 컨텍스트 세 개와 화면 안 `useState`를 씁니다.

| 컨텍스트 | 파일 | 주는 값 | 설명 |
| --- | --- | --- | --- |
| 로그인 `useAuth()` | `ui/ctx.jsx` (`AuthProvider`) | `me`, `ready`, `role`, `refresh()`, `login(loginId, password, keep)`, `loginWithToken(token)`, `logout()`, `unread`, `refreshUnread()` | `me`는 `/me` 응답(역할 `USER`·`ORG`·`ADMIN`, 이름, 기관명 등). 안 읽은 알림 수는 30초마다 다시 읽음. 로그인하면 카테고리(`loadCats`)와 큰 글씨 설정도 적용 |
| 화면 도구 `useUi()` | `ui/ctx.jsx` (`UiProvider`) | `toast(문장)`, `sheet(내용)`, `closeSheet()`, `confirm(제목, 본문, 확인 글자, 경고 여부)` | 토스트(2.3초), 바텀시트(한 번에 하나, Esc·바깥 클릭으로 닫힘, 닫으면 이전 초점으로 돌아감), 확인 시트(`Promise<boolean>`) |
| 모드 `useMode()` | `ui/proto.jsx` (`ModeProvider`) | `mode`(`'recv'` 또는 `'give'`), `setMode()`, `give`(참·거짓) | 사용자의 도움 받기 / 봉사하기 전역 모드. `MODE` 상수에 이름과 색 |

제공자 순서가 중요합니다: 시트 안의 화면 조각도 로그인 정보와 모드를 읽어야 해서 `UiProvider`가 가장 안쪽입니다(`App.jsx` 주석).

화면 데이터는 `useLoad`(읽기)와 `useBusy`(버튼 연타 방지)로 다룹니다(3장).

### 1-3. API 호출 (`api.js`)
| 이름 | 형식 | 설명 |
| --- | --- | --- |
| `api(path, opts)` | `opts: { method='GET', body, quiet=false, form }` → `Promise<data>` | `/api` + 경로로 호출. 토큰을 머리글에 붙임. 실패하면 `ApiError`를 던지고, `quiet`가 아니면 오류 문장을 토스트로 보여 줌. 401이면 토큰을 지우고 로그인으로 |
| `get` / `post` / `put` / `del` | `post(path, body, opts)` 등 | `api`의 짧은 이름 |
| `ApiError` | `{ message, status, code, data }` | `code` 예: `NETWORK`, `PII_NOT_ALLOWED`, `CONSENT_REQUIRED` |
| `uploadFile(file)` | → `{ url }` | `/files`로 올림 |
| `fileBlobUrl(url)`, `isProtectedFile(url)`, `openFile(url)` | - | 올린 파일(`/api/files/…`)은 로그인해야 열 수 있어서, 머리글을 붙여 받아 온 뒤 임시 주소로 보여 줌 |
| `aiStatus()` | → `{ provider, model, stt, mode }` | AI 키가 있는지. 한 번만 부름 |
| `transcribe(blob)` | → 글 | 서버 음성 인식 |
| `getToken` / `setToken`, `setErrorHandler`, `setUnauthorizedHandler` | - | `ctx.jsx`가 씀. 화면에서는 직접 쓰지 않음 |

규칙: 화면에서 `fetch`를 직접 부르지 않습니다. 실패 토스트는 `api`가 띄우므로 화면에서는 `try { … } catch { /* 토스트 */ }`로만 감쌉니다.

### 1-4. 경로와 권한 (`App.jsx`)
```jsx
const U = ['USER'], O = ['ORG'], A = ['ADMIN'], UO = ['USER', 'ORG'];
const g = (el, roles) => <Guard roles={roles}>{el}</Guard>;
<Route path="/o/home" element={g(<OHome />, O)} />
```
| 규칙 | 설명 |
| --- | --- |
| `g(<화면 />, 역할)` | 로그인하지 않았으면 `/login`으로, 역할이 다르면 자기 역할의 홈(`HOME_OF`: 사용자 `/u/home`, 담당자 `/o/home`, 운영자 `/a/dash`)으로 보냄 |
| `g(<화면 />)` (역할 생략) | 로그인만 확인 (알림, 공지, 공고 상세, 내 정보 수정, 탈퇴) |
| 경로 앞머리 | 사용자 `/u/home`·`/board`·`/bank`·`/planner`·`/my…`, 담당자 `/o/…`, 운영자 `/a/…`, 가입·로그인은 앞머리 없음 |
| 같은 화면을 두 역할이 씀 | `/board`, `/post/:id`, `/req/:id`·`/o/reqs/:id`(`RequestDetail`), `/write/need`, `/regular`, `/recurring`, `/voice`, `/group/…`, `/news…`, `/public`, `/qna` — 주소의 `?elder=`로 "누구 대신"을 넘김 |

### 2-2. 상세

#### `Screen` — 화면 틀 (`ui/Frame.jsx`, 기본 내보내기)
역할: 헤더(뒤로 · 제목 · 알림 벨 · 역할 칩) + 본문 + 역할별 아래 탭. 주소가 바뀌면 본문 스크롤을 맨 위로, 이동 방향에 따라 화면 전환 움직임을 붙입니다.

| prop | 형식 | 필수 | 설명 |
| --- | --- | --- | --- |
| `title` | 글자 | - (기본 빈 글자) | 헤더 제목 |
| `back` | 참·거짓 | - | `false`면 뒤로 버튼 숨김(탭 첫 화면), `true`면 항상 보임. 안 주면 앱 안에서 넘어왔을 때만 보임 |
| `noHeader` | 참·거짓 | - | 헤더 없음(시작·온보딩) |
| `noTabs` | 참·거짓 | - | 아래 탭 숨김(상세·폼 화면) |
| `noBell` | 참·거짓 | - | 알림 벨 숨김 |
| `tab` | 글자(경로) | - | 켜질 탭을 직접 지정(예: 담당자가 `/board`를 볼 때 `/o/elders`) |
| `cls` | 글자 | - | 본문 `main.bd`에 더할 클래스 |
| `bodyRef` | ref | - | 본문 요소 ref(스크롤 제어) |
| `children` | 노드 | 필수 | 본문 |

주의점: ① 아래 탭은 `ROLES[역할].tabs`에서 나옵니다. 사용자 `홈 · 공고 · 플래너 · 시간 통장 · 마이`(11/13 지시로 `홈 · 공고 · 시간 통장 · 플래너 · 마이`로 바꾸는 중), 담당자 `홈 · 도움 대상 · 편성표 · 요청 관리 · 리포트 · 마이`, 운영자 `대시보드 · 승인 · 신고·점검 · 관리`. ② 역할 칩을 누르면 데모 계정·모드 바꾸기 시트가 열립니다. ③ 운영자는 벨이 없습니다. ④ **모바일 틀입니다.** 담당자·운영자 PC 화면은 이 틀 대신 6장의 `PcShell`을 씁니다.

#### `Ic` — 아이콘 (`ui/bits.jsx`)
| prop | 형식 | 필수 | 설명 |
| --- | --- | --- | --- |
| `n` | 글자 | `h`가 없으면 필수 | `ui/icons.js`의 `I`에 있는 이름(`home`, `search`, `cal`, `wallet`, `user`, `users`, `list`, `chart`, `shield`, `flag`, `gear`, `bell`, `file`, `check`, `pen`, `msg`, `clock`, `spark`, `building`, `qr`, `logout` 등) |
| `s` | 숫자 | - | 크기(px). 주면 `ic(n, s)`로 크기를 넣어 그림 |

## 7. 재사용 지침과 정리할 것

### 7-1. 재사용 지침
1. **새 스타일 체계를 만들지 않습니다.** CSS 모듈·Tailwind·UI 라이브러리를 새로 들이지 않고, 지금처럼 클래스 이름 + CSS 파일로 갑니다. PC용은 `styles/pc.css` 하나에 `.pc` 아래로.
2. **화면 틀은 두 가지뿐**: 모바일 `Screen`, PC `PcShell`. 담당자·운영자 화면은 `PcShell`만 씁니다.
3. **서버 호출은 `api.js`만**, 읽기는 `useLoad`, 버튼은 `useBusy`. 읽는 중 `Loading`, 없으면 `Empty` — 모든 목록·표에 세 상태(읽는 중·없음·있음)를 넣습니다.
4. **토스트·확인은 `useUi()`**. PC에서도 그대로 씁니다. 패널·창만 새 컴포넌트.
5. **숫자·순위·상태는 서버 값을 그대로** 보여 줍니다. 화면에서 다시 계산하지 않습니다(평점·적립 시간·순위·건수).
6. **AI 결과는 `AiCard` 하나로**, 근거 한 줄을 꼭 붙이고 `source`가 `rule`이면 규칙 모드 표시.
7. **이름을 가리는 규칙**: 봉사자에게 보이는 관리 대상 이름은 `maskN`. 담당자 화면에서만 실명.
8. **경로는 그대로 두고 틀만 바꿉니다**(제안): `/o/…`, `/a/…` 주소는 유지하고 화면 컴포넌트를 PC 모양으로 바꿉니다. 목록 + 상세 화면은 상세 주소(`/o/elders/:id`)로 들어와도 목록 + 그 상세가 보이게 합니다(알림·예전 링크가 깨지지 않게).
9. **공용 화면 주의**: `Board`, `RequestDetail`, `WriteNeed`, `GroupNew`, `Notif`는 사용자와 담당자가 같이 씁니다. 담당자 PC용을 만들 때 이 파일을 직접 고치면 사용자 화면이 바뀝니다 → 안쪽 조각(예: 요청 상세의 처리 카드, 메시지)을 떼어 내 두 틀에서 같이 쓰는 방식으로.
10. **지금 사용자 화면 담당이 고치는 파일**(`home.jsx`, `board.jsx`, `bank.jsx`, `planner.jsx`, `my.jsx`, `Frame.jsx`, `u1113.css`)은 PC 작업에서 건드리지 않습니다.
11. 접근성: 누르는 `div`에는 `role="button"`, `tabIndex={0}`, Enter 처리(지금 코드 방식). 패널·창은 `role="dialog"`, Esc로 닫기, 초점 돌려놓기. 표는 `<table>`과 `scope`.
