| 구분 | 내용 |
|---|---|
| 이 파일 | 되돌봄(시간 적금) 기관 담당자(역할 ORG) 컴포넌트 명세서. API · SQL · 화면 이동 · 예외는 「기능-명세서-기관담당자.xlsx」에 있다. 이후 "되돌봄"으로 적는다. |
| 시트 구성 | 공통 컴포넌트(2개 이상 화면에서 쓰는 부품 · 맨 위에 기준 · 폴더 구조 · 공통 스타일 · 공통 훅·헬퍼) / 페이지 전용 컴포넌트(그 화면에서만 쓰는 부품) / 비고 |
| 기능 명세서와의 연결 | 기능 명세서 화면 시트의 「공통 컴포넌트」 칸에 적힌 <이름>은 이 파일 「공통 컴포넌트」 시트 B열(컴포넌트)의 이름과 글자까지 같다. 「화면 구성」 칸에 적힌 것은 「페이지 전용 컴포넌트」 시트에서 찾는다. 두 파일의 이름이 어긋나지 않는지 스크립트로 대조했다(check2.py). |
| 쓰는 페이지 | 「쓰는 페이지」의 화면 이름은 기능 명세서 A열의 화면 이름과 같다. "모든 화면" · "모든 PC 화면" · "대부분 화면"은 묶어 적은 것. 사용자·운영자 화면에서도 쓰는 부품은 비고에 "※ …에서도 쓴다"로 적었다. |
| 예시 형식과 다른 점 | 예시는 components/common/Button.jsx 처럼 부품마다 파일이 있지만 되돌봄 코드는 한 파일에 여러 컴포넌트가 들어 있다. 그래서 「구분」을 폴더가 아니라 파일로 묶고, 「파일 경로」에 정의된 줄 번호를 같이 적었다. 버튼 · 입력칸 · 바텀시트 · 토스트는 컴포넌트가 아니라 CSS 클래스와 UiProvider(useUi)로 처리한다. |
| 같이 쓰는 팀원 | 코드에서 어느 역할의 화면이 그 부품을 가져다 쓰는지를 보고 적었다(담당자 화면만 / 사용자 · 담당자 화면 / 담당자 · 운영자 화면 / 전원). 담당 팀원 이름은 코드로 확인할 수 없어 적지 않았다. |
| PC · 좁은 화면 | 폭 901px 이상이고 역할이 ORG 면 PC 틀(PcLayout), 좁으면 같은 주소에서 좁은 화면(모바일) 본문이 나온다. 경로에 걸린 함수(OHome · OReqs · Elders · OSchedule …)가 usePc() 로 둘 가운데 하나를 고른다. 부르는 API 와 동작은 같고 배치만 다르다. |
| 화면이 없는 기능 | 권한 위임 · 기관 공고 3종 · 홈 봉사자 현황 · AI 도우미는 서버 API 만 있고 프론트 컴포넌트가 없다(기능 명세서 「추가 기능(서버만)」 시트). |
| 서비스 규칙 | 관리 대상은 별칭 · 나이대 · 동만 저장한다(실명 · 주소 · 연락처 저장 안 함 · 봉사자에게는 별칭도 가려서 보임) / 수락 · 거부 · 이관 · 종료 같은 결정은 사람이 누른다 / 진단하지 않는다 / 숫자 · 순서는 코드가 계산하고 AI 는 설명 문장만 만든다 / 1시간 활동 = 1시간 적립(가중치 없음). |
