## 1. 개요

### 1.1 서비스 소개

시간 적금은 이웃을 도운 시간을 "시간 통장"에 적립해 두었다가 나중에 내가 도움을 받을 때 쓰는 시간 은행 서비스다. 1시간 도우면 1시간(난이도에 따라 1.0·1.2배 — 2026-11-13 결정: 기본 1.0·수고 1.2만)이 쌓이고, 돈으로 바꾸거나 사고팔 수 없으며 가족에게만 선물할 수 있다. 한 계정으로 봉사도 하고 도움도 받는다. 주민센터 같은 기관의 담당자는 앱을 쓰기 어려운 어르신(관리 대상)을 대신해 도움을 요청하고 확인하며, 이 경우 어르신 쪽 시간은 차감하지 않는다. AI는 공고 정리·일지 다듬기·추천 이유·리포트 문장처럼 "글"을 돕고, 시간 계산과 수락·확정 같은 결정은 코드와 사람이 한다.

### 1.2 액터

| 액터 | 설명 | 기기 |
|---|---|---|
| 사용자 — 봉사하는 사용자 | 신분증 인증과 첫 활동 교육을 마치고 도움 요청 공고에 제안하거나 봉사 가능 공고를 올린다. 활동 뒤 일지를 내고 시간을 적립한다 | 모바일(PC에서도 모바일 모양) |
| 사용자 — 봉사받는 사용자 | 도움 요청 공고를 올리거나 봉사 가능 공고·단골에게 요청한다. 활동을 확인하면 시간이 차감된다. 같은 계정이 헤더에서 두 역할을 바꾼다 | 모바일 |
| 기관 담당자 | 승인된 기관(주민센터·복지관 등) 소속. 관리 대상을 등록하고 대신 요청·수락·확인·평가한다. 편성표·리포트·특보·공공 서비스 연계를 본다. 봉사를 하려면 사용자 계정을 따로 만든다 | PC (지금 구현은 모바일 모양, 4.2 참고) |
| 운영자 | 기관·담당자·봉사자 승인, 신고·문의·공지, 통계·재정 추계·특보를 맡는다 | PC (지금 구현은 모바일 모양) |
| 시스템 | 상태 흐름, 시간 계산, 24시간 기한, 지각·노쇼 감지, 자동 마감·자동 확정, 정기 요청 회차 생성을 처리하는 서버(스케줄러 포함) | - |

### 1.3 용어

| 용어 | 뜻 |
|---|---|
| 공고 | 날짜·시간 범위·지역·카테고리를 적어 올린 글. **도움 요청 공고**(봉사받는 쪽이 올림, 코드 `NEED`)와 **봉사 가능 공고**(봉사하는 쪽이 올림, `OFFER`) 두 방향이 있다. 공고 1개는 수락된 요청 1건만 받는다 |
| 요청·제안 | 공고에 보내는 신청. 봉사 가능 공고에 보내면 **요청**(`REQUEST`), 도움 요청 공고에 보내면 **제안**(`PROPOSAL`), 공고 없이 단골에게 바로 보내면 **단골 요청**(`REGULAR`) |
| 최종 수락 | 봉사자가 요청을 수락한 뒤 도움 받는 사람(관리 대상은 담당자)이 한 번 더 수락하는 단계. 이때 일정이 **확정**된다 |
| 관리 대상 | 담당자가 등록해 대신 챙기는 어르신. 41판의 "독거노인", 화면의 "도움 대상"과 같은 말이다. 계정이 없고 시간 차감이 없다 |
| 별칭 | 관리 대상을 구분하는 이름. 봉사자에게는 "이○례 님"처럼 가려서 보인다 |
| 이슈 메모·방문 주의사항 | 관리 대상의 특이사항(귀가 어두움, 반려견 등). 일정이 확정된 봉사자와 담당자에게만 보인다 |
| 단골 | 같은 상대와 완료 3회 이상이면 자동으로, 또는 직접 등록해 맺는 관계. 단골에게는 공고 없이 요청할 수 있다 |
| 시간 통장 | 사용자마다 하나인 시간 계좌. 통장 번호, 쓸 수 있는 시간, 묶인 시간, 누적 번 시간·쓴 시간, 거래 내역을 가진다 |
| 보류(묶인 시간) | 일정이 확정될 때 받는 쪽 통장에서 예상 시간만큼 잠가 두는 것(`HOLD`) |
| 차감 | 활동이 완료될 때 보류를 풀고 실제로 빼는 것(`USE`) |
| 난이도 가중치 | 기본 1.0 / 수고 1.2 (2026-11-13 결정: 기본 1.0·수고 1.2만. 책임 1.5는 예전 기록에만 남는다). 카테고리로 기본 등급이 정해지고 AI(또는 규칙)가 요청 문장에서 등급과 근거를 제안한다 |
| 예정 시간 | 요청·제안에서 정한 활동 시간(30분 단위, 0.5~4시간). 적립·차감의 기준이다 |
| 활동 일지 | 봉사자가 활동 뒤 내는 한 줄 기록(과 사진). 일지가 있어야 적립이 확정된다 |
| 자동 확정 | 일지 제출 뒤 24시간 동안 받는 쪽이 확인하지 않으면 완료로 처리하는 것 |
| 정기 요청 | 매주 한 요일·시간을 등록해 두면 회차마다 도움 요청 공고가 자동으로 올라가는 것 |
| 단체 봉사 | 2명 이상이 함께 하는 봉사. 1:1 공고와 다른 흐름이며 받는 쪽이 늘 기관이라 차감이 없다 |
| 돌봄 편성표 | 담당자가 관리 대상의 주간 일정을 표로 보는 화면. 빈 칸에 대안을 추천받고 공고를 한꺼번에 올린다 |
| 권한 위임 | (PC명세, 아직 없음) 관리 대상이 담당자에게 "대신 공고·대신 수락·일지 확인·공공 서비스·안부 확인" 가운데 맡길 일과 기간을 정해 동의하는 것 |
| 기관 공고 | (PC명세, 일부만 있음) 기관 이름으로 동네 전체에 올리는 공고. 봉사자 모집 / 단체 봉사 / 해 드려요 세 종류 |
| 공공 서비스 연계 | 사용자가 공공 서비스 안내 AI의 대화를 "담당자에게 전달하기"로 보내면 담당자가 연락·신청을 돕는 흐름 |
| 특보 알림 | 운영자가 기상 특보 리포트를 공지와 담당자 알림으로 전달하고, 담당자가 자기 대상 기준으로 보는 것 |
| 규칙 모드 | AI 키가 없거나 AI 응답이 검사를 통과하지 못했을 때 코드가 만든 문장으로 대신하는 것(응답 `source: rule`) |

| 접두 | 뜻 | 번호 |
|---|---|---|
| `REQ-공통-NNN` | 모든 액터 또는 가입·인증·알림·고객지원 | 001~ |
| `REQ-사용자-NNN` | 봉사하는 사용자·봉사받는 사용자 | 001~ |

| `NFR-NNN` | 비기능 요구사항 | 001~ |
| `BR-NNN` | 업무 규칙 | 001~ |

- **출처** 칸으로 원래 문서를 추적한다. 예: `41판 B-24 / 기능 U-16 / 11/13`.
- **우선순위**: 기능명세서의 상·중·하를 그대로 썼다(상 = 발표 시연에 꼭 필요, 중 = 있으면 좋음, 하 = 시간 남으면). 기능명세서에 없는 항목은 문서 담당이 판단해 정하고 `*`를 붙였다(예: `중*`).
- **상태**

| 상태 | 뜻 |
|---|---|
| 구현됨 | 기준 커밋의 코드에 동작이 있다(모의·가정값 단서는 비고에) |
| 일부 | 일부만 있거나, 명세와 다르게 되어 있거나, 미커밋 작업 중이다 |
| 미구현 | 요구는 정해졌지만 코드가 없다 |
| 미정 | 회의·대표 결정이 먼저 필요하다(코드도 없다) |
