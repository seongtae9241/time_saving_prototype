# LLM 기능 아이디어 기록

아이디어 팀이 낸 제안을 회차별로 모아 둡니다. **아직 채택된 것은 없습니다.** 구현 여부는 대표 결정입니다.
효과는 모두 추정이고, 실제 5060·7080 사용자에게 써 보게 해야 확인됩니다.

## 1회차 (2026-11-11) — 있는 기능을 편하게 · 결과: 퇴짜 ("식상한 보완뿐")

## 2회차 (2026-11-11) — 서비스의 풀리지 않은 문제에서 출발한 3개 · 결과: 보류 (다시 찾기로)

팀이 뽑은 문제: ① 20년 약속에 담보가 없다 ② 시간이 한 방향으로만 흐른다(7080은 받기만, 10시간 적립 조건) ③ 말동무가 아무것도 남기지 않는다

### 1. 미래의 나에게 — 시간과 함께 "나를 돕는 법"이 쌓이는 통장
- 봉사를 마칠 때마다 AI가 **오늘 일지에서** 질문 하나를 만들어 묻고(돕던 자리를 받는 자리로 뒤집어), 답이 20년 뒤 나를 도울 봉사자에게 건네짐.
- LLM인 이유: 질문이 일지마다 달라 규칙으로 못 만듦. 고정 설문이면 남의 일처럼 답함.
- 필요한 이유: 통장에 숫자 말고 내용물이 생김. 한계: 서비스 20년 존속 신뢰는 못 풂.
- 부담: 새 메뉴 0, 일지 완료 화면에 질문 한 줄. AI 호출 추가 없음. 불확실: 응답률.

### 2. 거꾸로 부탁 — 받기만 하던 분께 부탁장이 먼저 옴
- 봉사 등록을 안 한 분의 소개글·기록에서 "줄 수 있는 것"을 찾아 동네 실제 요청과 이어 부탁장을 보냄. 본인이 누르고 상대가 수락(자동 매칭 아님).
- LLM인 이유: 재주와 진짜 필요가 둘 다 문장 속에만 있음.
- 필요한 이유: 시간이 한쪽으로만 흐르는 구조를 풂. 받는 분이 벌 곳이 생김.
- 부담: 홈 카드 1장, 거절하면 한 달 쉼. 독거노인 제외. 불확실: 70대가 반길지.

### 3. 이어 듣는 이야기 — 말동무가 올 때마다 이야기가 한 쪽씩
- 봉사자가 남긴 "오늘 들은 이야기"를 방문을 넘어 이어 붙이고, 빠진 대목을 다음 질문으로 봉사자에게. 본인이 확인한 장만 가족에게.
- LLM인 이유: 조각 메모를 꿰고 빈 곳을 찾아 다음 만남을 바꿈.
- 필요한 이유: AI 말벗을 금지한 대신 사람 말동무가 남기는 것이 생김.
- 부담: 가장 큼. 새 입력 필요, 가족사 등 민감 정보 → 본인 동의·장별 확인·법무 확인, 유료 AI 등급 전제.

### 버린 것 중 아까운 것
돌봄 이어달리기 설계(상황을 가벼운 일 여러 개로 쪼개기), 첫 만남 공통점 찾기, 시간의 족보(내 1시간이 누구를 거쳐 돌았는지)

## 3회차 (2026-11-11) — LLM이 중심 엔진인 대표 기능 3개 · 결과: 방향 승인("이런 느낌으로 더 찾아줘"). 구현 여부는 아직 미정

팀의 2회차 실패 진단: 화면에서 작았고(문장 한 줄), 효과가 정서 쪽이라 가입·매칭·도입과 이어지지 않았으며, "새 화면 0"을 장점으로 내세워 스스로 작게 만들었다.

### 1. 전화 창구 — 앱을 못 쓰는 어르신이 전화 한 통으로 알림을 듣고 그 자리에서 답한다
- 지금 로그만 남기는 B-42(음성 전화 알림)를, 전화를 걸어 용건을 말하고 대답을 알아듣고 본인 결정을 받는 통화 에이전트로.
- LLM(통화 1건 3~6회): 용건 대본 → 턴마다 음성 이해(수락·거부·시간 변경·되묻기·새 요청·위급) → 일정·잔액 조회해 답 → 복창 → 통화 결과 정리.
- LLM 없으면: "1번 수락, 2번 거부" ARS만 남음. "세 시로 바뀌었는데" 같은 말을 못 받음.
- 필요한 이유: 최종 수락을 24시간 안에 안 하면 만료되고 공고도 다시 안 열림(B-19). 7080이 앱 알림을 못 보면 요청이 죽고 시간이 돌지 않음.
- 사람 결정: 말한 뒤 숫자키로 확정. 시간 변경·새 요청은 초안만. 잡담이 길면 말동무 요청으로 안내(AI 말벗 아님). 녹음 저장 안 함.
- 크기: 브라우저 통화 시뮬레이터 시연까지 중간. 실제 전화는 전화망 업체 계약·통화료 필요(금액 모름). 불확실: 사투리·고령 발화 인식률.

### 2. 주간 돌봄 편성표 — 담당 어르신 전원의 한 주를 통째로 짜서 한 번에 승인
- 담당자가 버튼을 누르면 대상 × 요일 편성안이 이유와 함께 나오고, 말로 고친 뒤 "9건 보내기".
- LLM(주 1회 3~4회 + 수정마다 1회): 주의사항·전달 메모·방문 패턴에서 이번 주 할 일 뽑기 → 코드가 후보 봉사자 조회 → 전체 배정과 이유·빈칸 대안 → 코드 검증(시간 겹침·4시간·받지 않기) → 말로 고치기.
- 필요한 이유: 독거노인 등록은 기관 경로뿐(C-01). 지금은 건별 작업이라 대상이 늘수록 담당자 부담이 늘어남. 기관이 도입할 이유.
- 사람 결정: 담당자 일괄 승인(줄별 해제), 봉사자는 각자 수락. 자동 매칭 아님.
- 크기: 큼. 불확실: 편성 품질, 대상 5명 이하 기관은 체감 작음.

### 3. 돌봄 설계 — 상황 한마디를 2주치 돌봄 계획으로
- "엄마가 다음 주 금요일에 퇴원하세요" → 되묻기 최대 2번 → 가벼운 일 여러 건의 일정표 + 필요 시간 합계와 내 잔액 + 못 하는 일은 공공 서비스 연결 → 버튼 하나로 묶음 등록.
- LLM(계획 1건 3~5회): 상황 이해 → 과업 분해(금지 필터 통과) → 코드가 예산 계산 → 일정 배치·줄인 안 → 미매칭 시 재설계.
- 필요한 이유: 5060이 가입하는 현실적 계기는 지금 부모에게 일이 생긴 순간. 쌓은 시간이 쓰이는 장면을 보여 줌.
- 사람 결정: 본인 승인, 건별 제외 가능. 회복 기간 같은 건강 추론은 안 함.
- 참고(총괄 확인): 가족 대신 요청하는 입구는 이미 있음(`my.jsx`의 "가족 대신 도움 요청"). 팀은 없다고 봤으나 사실과 다름.
- 크기: 중~대. 2번과 "계획 → 일괄 승인" 엔진 공유 가능. 불확실: 봉사자가 부족하면 계획만 크고 매칭이 안 됨.

### 버린 것 중 아까운 것
운영 관제 에이전트(매일 밤 수급·균형 조사 후 조치 묶음), 우편물·안내문 사진 읽기(주민번호·금융 정보 위험), 펑크 대타 조율(2번에 흡수 가능)

## 4회차 (2026-11-11) — 3회차와 같은 느낌으로 새 기능 6개 · 결과: 대표 검토 대기

코드에서 확인한 바탕 사실(총괄 재확인 포함)
- 신분증 승인 전에는 봉사 공고·요청·제안을 서버가 막음. **안전 교육 미수료는 서버가 막지 않음**(배지·추천 가점만) — 요구사항 B-01과 다름, 팀 결정 필요.
- 활동 중 봉사자 화면에는 QR과 긴급 버튼만 있음. AI에 사진을 넣는 호출은 아직 없음(오디오만).
- 도움 대상 등록은 한 명씩만 가능(일괄 등록 없음).
- 신고 처리에 상대방 이야기를 듣는 절차가 없음(운영자가 조치를 고르면 통보).
- **가족 대신 요청은 화면에서 공고 제목·안내에 가족 이름을 붙이는 수준**이고 서버에는 가족 처리(가족 통장 차감 등)가 없음 → 3회차 "돌봄 설계"를 부모 대신 쓰려면 이 부분 정책·개발이 필요(3회차 기록의 "입구가 이미 있음"은 화면 입구만 맞음).

주의·한계
- 2·4는 화면 사진·장부에 개인정보가 들어가 **무료 Gemini로는 실사용 불가**(유료 등급 전제). 4는 기관이 장부를 올려도 되는지 법무 확인 필요. 2는 봉사자가 범용 AI 앱으로도 할 수 있다는 반론이 셈.
- 3의 최악 오판은 "금지인데 허용". 애매하면 무조건 "주의 + 담당자에게 물어보기"로.
- 5는 회원 데이터가 쌓인 뒤에야 실효. 6은 사건이 드물면 시연 임팩트가 약함(영업 자료 가치).
- 1은 열린 요청이 적은 동네에서는 준비표가 빈약.

### 팀이 추천한 9개(3회차 3 + 4회차 6) 제작 순서

## 대표 제안 (2026-11-11) — "여기 눌러요": 어르신이 말로 물으면 AI가 화면을 찾아 주고 누를 곳을 짚어 준다 · "같이 보기"를 대체

**한 줄 정의**: 어느 화면에서든 "이거 으뜨케 혀~" 하고 말하면, AI가 말·지금 화면·그 사람의 현재 상황을 함께 읽어 해당 화면으로 데려가고 누를 버튼을 짚어 소리로 안내한다.

**시연 장면**
- 어르신(요청 상세 화면에서): "이거 으뜨케 혀?"
- AI: "김하늘 학생이 수요일 두 시에 병원 같이 가 주겠대요. 받으시려면 아래 초록색 '최종 수락'을 누르세요." (버튼이 반짝임)
- "시간 냄겨 놓은 거 딸한테 주고 싶은디" → 통장 → 가족 고르기 → 시간 정하기 → 보내기를 한 단계씩 따라가며 짚어 줌.

**동작**
1. 모든 화면 같은 자리의 큰 마이크를 누르고 말한다.
2. AI가 ① 말(사투리, "이거·그거") ② 지금 화면 ③ 현재 상황(요청 단계·잔액·다가오는 일정)을 함께 읽는다.
3. 해당 화면으로 이동하고, 누를 버튼에 표시를 띄우고, 소리로 안내한다. 여러 단계면 한 단계씩.
4. **누르는 것은 어르신이 직접.** 수락·취소·보내기는 AI가 대신 누르지 않는다.

**왜 LLM인가**
- 같은 "이거 어떻게 해"라도 수락 대기 중이면 수락 버튼, 활동이 끝났으면 확인 버튼, 통장 화면이면 선물하기 — 화면과 상황으로 "이거"를 알아내야 한다.
- "그 총각 언제 온댜", "시간 냄겨 놓은 거" 같은 말은 메뉴 검색·도움말 목록으로 못 받는다.

**왜 필요한가**
- 받는 쪽이 7080인데 앱을 못 쓰면 요청·수락·확인이 안 되고(24시간 지나면 만료), 시간이 돌지 않는다. 전화 창구(3회차)가 앱 밖 통로라면 이것은 앱 안 통로.

**"같이 보기"보다 나은 점**
- 사진이 필요 없어 개인정보 문제가 없고 무료 Gemini로 가능.
- 우리 앱 화면 구조와 그 사람의 상태는 우리만 알아서, 다른 AI 앱으로 대체되지 않는다.

**약점·주의**
- 지금 있는 "물어보기"(잔액·일정 답, 일부 화면 열기)와 겹침 → 새 기능으로 따로 두지 않고 **물어보기를 이것으로 키운다**(입구 하나 유지).
- 마이크를 못 찾으면 소용없음 → 모든 화면 같은 자리에 크게. 오래 멈춰 있으면 먼저 "도와드릴까요?"를 띄우는 것은 써 보고 결정.
- 엉뚱한 버튼을 짚을 위험 → 짚을 수 있는 버튼 목록은 코드가 정하고 AI는 그 안에서만 고름. 헷갈리면 두 개를 보여 주고 되묻기.
- 사투리·고령 목소리 인식률은 써 봐야 앎.

**크기**: 중간. 있는 것 = 음성 인식, 물어보기 화면, 화면 이동. 새로 필요 = 화면별 "할 수 있는 일" 지도, 버튼 짚기 표시, 단계별 따라가기.
**상태**: 대표 제안, 총괄 추천. 구현 여부 미정.
