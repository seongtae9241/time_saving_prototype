# 2026-11-09 팀 회의 반영 계획

회의 메모와 LLM 기능 추가 요청을 개발 작업으로 정리했습니다. 회의에서 결론이 갈린 항목은 **총괄이 결정한 내용**을 적고 이유를 붙였습니다. 다르게 가고 싶으면 이 문서에서 고치면 됩니다.

## 0. 서비스 방향 (회의 결론)
- **주 대상은 5060세대**입니다. 지금 시간을 쌓아 두고 7080세대에 받는 구조입니다. 봉사를 좋아하는 젊은 사람도 쓸 수 있지만, 젊은 층을 따로 겨냥하지는 않습니다.
- 봉사는 **가볍게 주고받을 수 있어야** 합니다.
- **시간은 평등하게 셉니다.** 1시간 했으면 1시간을 법니다.

## 1. 사용자 화면

| # | 회의 내용 | 반영 |
|---|---|---|
| U1 | 전체 적립시간·전체 사용시간은 시간 통장에 | 시간 통장 맨 위에 "전체 적립 / 전체 사용 / 남은 시간"을 보여 주고, 홈 카드는 짧게 줄임 |

| U3 | 봉사받고 싶은 사람에게는 자주 받는 봉사가 앞에 | 내 요청·완료 기록에서 카테고리 순위를 계산해, 홈 추천·공고 필터 칩·공고 목록 정렬에 반영("내가 자주 받는 도움" 우선) |

| U7 | 단골 등록(자동이든 수동이든) | 자동(3회 이상)은 그대로 두고, **수동 "단골로 등록"** 버튼을 더함(활동이 끝난 상대의 프로필·요청 상세). 마이 → 내 단골에서 해제 가능 |
| U8 | 내 위치 기준 공공 서비스를 LLM이 찾기, DB에 저장하지 않음 | 공공 서비스 안내에 "내 위치로 찾기"를 둠. 브라우저 위치(동의할 때만) → 서버가 LLM 프롬프트에 위치를 넣어 요청 → 결과는 **저장하지 않고** 화면에만 보여 줌. "AI가 찾은 정보예요 · 꼭 기관에 확인하세요" 표시. 키가 없으면 기존 DB 안내로 대체 |
| U9 | QR이 뭐냐 | 만났을 때와 끝날 때 서로 확인하는 장치라 유지. 처음 쓸 때 한 줄 설명을 더함 |

## 2. 동네 클래스 → "동네 소식·클래스"로 범위 줄이기 (결정)

회의 의견이 갈렸던 지점과 결정:
- **기관 행사·클래스 홍보 페이지를 중심으로 바꿉니다.**
  - "알아서 모이라고 하기엔 고려할 게 너무 많다"는 의견과 "기관 이벤트 홍보가 낫다"는 의견이 많았습니다.
  - 탭 이름은 **"동네 소식"**입니다. 기관(담당자)이 행사·클래스를 올리고, **URL을 넣으면 그 페이지의 제목·이미지를 가져와** 카드로 보여 줍니다.
  - 신청은 앱 안에서 하거나 외부 링크로 갑니다.
- **사용자가 여는 클래스는 남기되 좁힙니다.**
  - 주제는 **정서(말벗·이야기) / 전자기기 사용법** 두 가지만 엽니다. 요리·손재주·일 경험 같은 높은 수준의 주제는 닫습니다. "심플한 것, 누구나 할 수 있는 것", "레벨이 높으면 안 됨"이라는 의견을 따랐습니다.
  - 1:1은 카페·도서관 같은 열린 곳에서 만납니다.
  - 여럿이 하는 수업은 **최대 4명이고, 기관이 신청해 장소를 정할 때만** 열립니다.
- **시간 정산은 평등하게 셉니다.**
  - 배우는 사람은 1시간을 쓰고, 여는 사람은 **참석한 사람 수 × 1시간**을 법니다. 4명이 오면 4시간입니다.
  - 기존의 "×0.5 수강료 + 준비 1시간" 계산은 없앱니다.

## 3. 담당자

| # | 회의 내용 | 반영 |
|---|---|---|
| O1 | 담당자가 봉사자를 거부할 수 있어야 함 | 담당 대상 건의 요청·제안·수락된 봉사자에 대해 **거부(사유 필수)**를 할 수 있게 함. 봉사자에게 알림이 가고, 그 봉사자는 그 대상에 다시 신청하지 못하게 막는 "이 봉사자 받지 않기"를 선택할 수 있음 |
| O2 | 담당자 공고는 명확해야 함 → LLM은 정리 용도로 | 담당자 대리 공고에 "AI로 정리하기"(입력한 글을 제목·내용·주의사항으로 다듬기)를 둠. 기존 대화형 작성은 유지 |
| O3 | 기관 행사 홍보 (URL로 제목·이미지 가져오기) | 2장 "동네 소식" |
| O4 | 요청 관리 | 좋다는 의견이라 유지 |

## 4. 리포트 (활동 메모 중심으로 바꾸기)

- **건별 활동 메모**: 봉사자가 활동을 마치고 일지를 쓸 때 "전달 메모"를 함께 남깁니다. 예: 병원에서 들은 말, 다음에 챙길 것.
  - 메모는 요청 상세에 건별로 보입니다.
  - **봉사받은 사람도 볼 수 있습니다.** 독거노인 건은 담당자가 봅니다.
- **"최근 활동" 리포트**: 한 달 생활 변화 리포트 대신 **최근 활동 목록(최신순)과 메모**를 먼저 보여 줍니다. 그 위에 AI가 최근 몇 건을 묶어 쓴 "인수인계 요약"을 둡니다. 담당자가 바뀌거나 새 봉사자가 올 때 씁니다.
- **누가 보나**:
  - 담당자는 담당 대상의 리포트를 봅니다.
  - 사용자는 내가 받은 도움의 리포트를 봅니다.
  - 가족은 공유에 동의한 경우만 봅니다.
- **봉사자에게 넘기는 정보는 기본 정보만**: 별칭·동·도움 내용·주의사항까지만 넘깁니다. 지난 메모 전체는 봉사자에게 보이지 않습니다. "모든 정보 공유는 좀 그렇다"는 의견을 따랐습니다.
- 병원에서 들은 말처럼 건강 정보가 들어가는 메모는 민감정보입니다. 보는 사람을 위 범위로 제한하고, 처리방침에 적어야 합니다(공개 전 법무 확인).

## 5. 운영자 대시보드

- 나이대별 인기 봉사, 계절(월)별 인기 봉사, 카테고리별 수요·공급 차이, 지역별 매칭률(기존)을 보여 줍니다.
- **LLM 인사이트**:
  - 요청 대비 공급이 적은 카테고리와 그 이유를 짐작합니다.
  - 기존 6개 카테고리에 맞지 않는 요청 문장들을 모아 **새 카테고리 후보**를 제안합니다.
  - 숫자는 코드가 집계하고, LLM은 설명과 제안만 씁니다.
- **봉사 인증 항목**: 팀이 정해야 합니다(6장). 화면에는 지금 항목(신분증 필수, 범죄경력 회보서 선택, 안전 교육 필수)이 그대로 있습니다.

## 6. LLM 개인 분석 (추가 요청)

| 기능 | 내용 | 계산은 코드, 글은 LLM |
|---|---|---|
| 내 활동 분석 | 내가 도와준 기록과 도움받은 기록(카테고리·시간대·횟수·받은 평가)으로 "나는 어떤 도움을 잘 주고, 어떤 도움을 자주 받는지" 분석 | 횟수·비율은 코드 |
| 내 평가 습관 분석 | 내가 남긴 별점·태그·한마디를 보고 평가 성향(후한 편/꼼꼼한 편, 자주 쓰는 칭찬)을 알려 줌 | 평균·분포는 코드 |
| 내가 받을 수 있는 봉사 플랜 | 지금 남은 시간으로 앞으로 어떻게 받을 수 있는지. 예: "말동무 주 2회 1시간씩이면 약 ○주", "병원 동행(1.5배) 월 2회면 ○개월". 원하는 카테고리·횟수를 고르면 다시 계산 | 기간 계산은 코드(가중치 포함), LLM은 설명·추천 조합 |

- 위치: 마이 → "AI 분석", 시간 통장 → "내 봉사 플랜".
- 키가 없으면 규칙 모드 문장(숫자 요약)으로 나옵니다.
