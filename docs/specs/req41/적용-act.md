# 요구사항 41판 적용 — 활동 진행·안전·신고 (가지 `req41-act`)

범위: B-51·B-52·B-53, C-11, B-36·B-37·D-02, A-07·B-50 알림 이동, B-12·B-13, B-25 앞부분, B-35, B-24(QR 시각).
`docs/design/contract.md`와 `backend/src/main/resources/db/schema.sql`은 고치지 않았다. 아래 ②·③을 총괄이 합친다.

## ① 고친 항목

| ID | 무엇을 어떻게 |
|---|---|
| B-51 QR 30초 갱신 | 일정이 확정될 때 요청마다 비밀값(`qr_secret`)을 만들고, 6자리 번호를 "비밀값 + 30초 구간 번호"로 계산한다(`Rules.rotatingCode`, HMAC-SHA256). 시작·종료 확인은 **지금 구간과 직전 구간**의 번호만 받는다. 확정 때 만들던 고정 6자리(`check_code`)는 더는 확인에 쓰지 않는다(예전 자료의 비밀값 대용으로만 남김). 받는 쪽 "내 QR 보여주기" 시트는 5초마다·남은 시간이 0이 될 때 서버에서 새 QR·번호를 받아 오고, 봉사자가 찍으면 저절로 닫힌다. 번호 6자리 입력 길은 그대로 있다(번호도 30초마다 바뀜). |
| B-51 30분 차이 안내 | 종료가 기록될 때(QR·번호·자동 마감 모두) 기록된 시간과 예정 시간이 30분 이상 다르면 봉사자와 받는 쪽(독거노인 건은 담당자)에게 알림 `TIME_GAP`을 한 번 보내고 메시지 창에 시스템 문장을 남긴다. 요청 상세·일지 화면에도 같은 안내가 뜬다. 적립은 예정 시간 기준 그대로다. |
| B-51 안내 문구(B-30 결정) | QR 첫 안내 "찍은 시간만큼 시간이 정확히 쌓여요" → "찍은 시각은 일지에 자동으로 들어가고, 시간은 미리 정한 예정 시간 기준으로 쌓여요". 일지·확인 화면의 "예정 시간"에 "정산 기준 / 적립 기준"을 붙였다. |
| B-24 QR 시각 자동 입력 | 일지 화면의 기록 줄을 "기록된 시각 … (자동 입력)"으로, 요청 상세의 일지 카드 아래에도 기록된 시각(자동 마감이면 그 표시)을 보여 준다. 시스템 메시지의 시작·종료 시각도 분 단위로 적는다. |
| B-52 지각·노쇼 감지 | 스케줄러 `lateCheck`: 예정 시작 **10분** 뒤 지각 알림 `LATE`, **30분** 뒤 노쇼 의심 알림 `NOSHOW_SUSPECT`를 봉사자와 받는 쪽에 각각 한 번씩(독거노인 건은 담당자). 노쇼 신고(`/noshow`)와 `noshow` 버튼은 15분 → **30분**부터. 봉사자 "늦는다고 알리기" 버튼은 시작 1시간 전부터 시작 기록 전까지 계속 보인다(전에는 10~30분 사이에만). 받는 쪽 "조금 더 기다릴게요" / "노쇼 신고·취소"는 그대로(30분부터). 하루 넘게 지난 예전 일정에는 뒤늦게 노쇼 의심 알림을 보내지 않는다. |
| B-53 자동 마감 | 스케줄러 `autoCloseDue`: 활동 중(IN_PROGRESS)인데 예정 종료 30분이 지나면 종료 시각을 **예정 종료 시각**으로 넣고 CHECKED_OUT으로 바꾼다. 봉사자에게 일지 작성 알림 `AUTO_CLOSED`, 받는 쪽에도 같은 종류 알림. 화면에 "종료 QR 기록이 없어 예정 종료 시각으로 자동 마감됐어요" 표시. |
| C-11 현관 QR 카드 | 도움 대상마다 카드 번호(`elders.qr_code`) 하나. 담당자가 도움 대상 화면 아래 메뉴 "현관 QR 카드"에서 보기·인쇄·다시 발급한다. 다시 발급하면 번호가 바뀌어 이전 카드는 `WRONG_CODE`로 걸린다. 독거노인 건의 시작·종료는 이 카드 번호로만 확인한다(받는 분 화면의 30초 번호는 받지 않음). 요청 상세의 "현관 QR 카드 보기·인쇄"도 요청별 번호가 아니라 이 대상 카드를 보여 준다. 카드는 일정이 확정될 때 없으면 자동으로 만들어진다. QR 글은 `TS1|ELD|<대상 id>|<번호>`. |
| B-36 안부 확인 | 신고 양식에 "이상 징후(안부 확인)" 유형(독거노인 활동의 봉사자·담당자에게만 보임, 내용 필수). 접수되면 그 대상의 담당자에게 알림 `WELFARE`(요청 화면으로 이동), 운영자에게는 "제재 없이 확인만 하는 기록" 알림. 긴급 시트는 119·112 전화 연결과 "운영자에게 신고 접수하기"만 남기고, 전에 있던 "담당자·운영자에게 긴급 알림 보내기"(메시지+'긴급 상황' 신고 자동 생성)는 뺐다. 요청 상세 아래에 "이상 징후(안부 확인) 알리기" 버튼. |
| B-37 신고 | 활동 상대(USER) 신고 버튼을 프로필 시트("이 분 신고하기")와 요청 상세 아래("활동 상대(○○ 님) 신고하기")에 추가. 서버는 USER 대상이 실제 있는 다른 사용자인지 확인한다. 접수 문구는 프로토타입대로 "신고를 접수했어요. 운영자가 확인해요". |
| D-02 구분 표시 | 운영자 신고·점검 화면에 "안부 확인 접수 n건 · 제재 없음 · 기록 확인용" 구역을 따로 두고, 일반 신고 목록·처리한 신고 목록에서는 뺐다. 처리 시트는 경고·정지·퇴출 선택 없이 "기록 확인"만. 서버도 이상 징후 접수에 제재 값을 보내면 400 `NO_SANCTION`. |
| A-07·B-37·B-50 알림 이동 | `goLink`가 서버 링크를 화면 경로로 바꾼다: `/requests/N`→요청 상세, `/posts/N`→공고, `/my/inquiries`·`/my/reports`→문의·신고 내역(`/qna`), `/family/N/report`→가족 월별 리포트, `/org/elders/N`·`/org/transfers`·`/org/reports`→담당자 화면, `/admin/reports`·`inquiries`·`orgs`·`verifications`·`appeals`→운영자 화면. 서버 링크 문자열은 그대로 뒀다. "모두 읽음"은 이미 있었다(확인만). 새 알림 종류 아이콘 추가. |
| B-12 소개 카드 사진 | 소개 카드·프로필 시트·상대 카드에 `photoUrl`이 있으면 사진을 보여 준다(`Avatar`에 `photo` 속성, 없으면 이름 첫 글자). |
| B-13 나이대 | 요청 응답의 `elder`에서 `ageGroup`은 담당자에게만 넣는다(`Views.elderBrief`). |

| B-35 방문 중 안전 | 요청 상세(사용자·담당자 공통)에 일정 확정~활동 중 동안 "방문 중 안전 규칙" 띠: 신체 접촉 금지, 방문 외 개인 연락·연락처 교환·금전 요구 금지, 신고·119·112 안내. |

## ② 새 API · 바뀐 API

새 API
- `GET /api/requests/{id}/qr` (받는 사람·담당자만) → `{status, elderCard, code, qrText, leftSec, stepSec:30}`. 일반 건은 지금 구간의 번호와 남은 초, 독거노인 건은 현관 카드 번호(`leftSec` 없음). 확정·활동 중이 아니면 `code`·`qrText`는 null.
- `GET /api/org/elders/{id}/qr-card` (담당 담당자만) → `{elderId, displayName, code, qrText:"TS1|ELD|id|code", issuedAt, activeCount}`. 카드가 없으면 만든다.
- `POST /api/org/elders/{id}/qr-card/reissue` → 같은 모양. 번호가 바뀐다. 종료된 대상은 400 `ELDER_ENDED`.

바뀐 API
- `POST /api/requests/{id}/check-in`·`check-out` `{code, method}`: `code`는 일반 건이면 지금·직전 30초 구간의 번호, 독거노인 건이면 현관 카드 번호. 틀리면 400 `WRONG_CODE`. `method:'manual'`(번호 없이)은 그대로 남아 있다.
- `POST /api/requests/{id}/noshow`: 시작 30분 전이면 409 `TOO_EARLY`(전에는 15분).
- `POST /api/requests/{id}/cancel`: 상태가 SENT일 때 받은 쪽이 부르면 403.
- RequestView: `checkCode`·`qrText`는 받는 쪽·담당자에게 **확정·활동 중일 때만**. 일반 건은 30초 번호 + `qrLeftSec`, 독거노인 건은 현관 카드 번호 + `elderCard:true`, `qrIssuedAt`. 모든 역할에 `autoClosed`, `gapMinutes`(기록 − 예정, 분. 종료 전에는 null) 추가. `elder.ageGroup`은 담당자에게만. `actions`의 `noshow`는 30분부터.
- `POST /api/reports` 본문에 `kind` 추가(선택). `kind:"WELFARE"` 또는 `type:"이상 징후(안부 확인)"`이면 이상 징후 접수: 대상은 독거노인 활동(REQUEST)이어야 하고(아니면 400 `NOT_ELDER_ACTIVITY`), 그 활동의 봉사자·담당자만(403), 내용 필수(400 `CONTENT_REQUIRED`). 응답 Report에 `kind`, `elderId`. `targetType:"USER"`는 없는 사용자·나 자신이면 400.
- `GET /api/admin/reports` 항목에 `kind`, `welfare`, (이상 징후면) `elder{id, displayName(가린 별칭), dong}`, `manager{id,name}`, `targetUser:null`.
- `POST /api/admin/reports/{id}/handle`: 이상 징후 접수는 `action`이 `NONE`만 가능(다른 값 400 `NO_SANCTION`), 결과 기본 문구 "접수 기록 확인", 접수한 사람에게 알림.
- `GET /api/org/elders`·`/{id}` 항목에 `qrIssuedAt`.
- `POST /api/admin/scheduler/run` 결과에 `autoClosed` 건수.
- 새 알림 종류: `NOSHOW_SUSPECT`, `AUTO_CLOSED`, `TIME_GAP`, `WELFARE`. `LATE`는 10분 기준으로 바뀜.
- QR 글 종류 추가: `TS1|ELD|<도움 대상 id>|<6자리>`.

계약서에서 고쳐야 할 옛 문장: 3.2 "시작 예정 15분이 지나도 체크인이 없으면…"(64줄 근처), 5.4 체크인 설명(152줄), 7.9 "QR 내용"(314줄).

## ④ 못 한 것 · 남은 것

- **화면을 브라우저로 눌러 보지 못했다.** 프런트는 빌드만 확인했다. 특히 "내 QR 보여주기"의 30초 갱신·자동 닫힘, 현관 카드 시트(인쇄·다시 발급), 운영자 안부 확인 구역은 화면 확인이 필요하다.
- **이미 있는 DB 파일에 새 칸이 붙는지는 확인하지 못했다.** 테스트는 빈 메모리 DB에서만 돌았다(`boolean default false` 칸 3개가 기존 `requests` 표에 추가되는지).
- **번호 없이 시작·마치기(`method:'manual'`)를 남겨 두었다.** 총괄 결정에 없어서 손대지 않았다. 이 길이 있으면 QR 없이도 시작·종료가 기록된다("받는 분 확인 필요" 표시는 붙음). 없앨지 결정 필요.
- "늦는다고 알리기"·"더 기다리기"는 전처럼 정해진 문장의 요청 메시지를 보내는 방식이다(상대에게 새 메시지 알림이 감). 따로 기록 칸은 만들지 않았다.
- 시작 기록이 끝내 없는 확정 일정(받는 쪽이 노쇼 신고도 취소도 안 함)은 CONFIRMED에 그대로 남는다. 명세에 정해진 처리가 없어 그대로 뒀다.
- 인쇄는 전과 같이 `window.print()`라 시트 뒤 화면도 함께 인쇄될 수 있다(카드만 인쇄하는 전용 스타일은 만들지 않음 — 새 스타일을 만들지 말라는 지시).
- B-36의 "일지 기반 변화 요약 알림은 최근 3건 중 2건" 조건(`CareSignalService`)은 내 범위 밖이라 그대로다.
- 운영자 대시보드의 처리 대기 신고 수에는 확인 전 안부 확인 접수도 함께 세어진다(`AdminController` 대시보드 부분은 범위 밖).
- 프로필·소개 카드의 `eduDone` 값 자체는 서버 응답에 아직 실린다(화면 표시만 뺌, B-54 담당 범위).

## ⑤ 확인 방법

- 서버 테스트: `cd backend && sh ./mvnw test` → 159건 통과(새 `Req41ActivityTest` 17건 포함). 기존 테스트 4개 파일은 시작·종료 번호를 `r.checkCode` 대신 `reqs.codeFor(r)`로 바꿨다.
- 프런트: `cd frontend && npm run build` 성공.
- 손으로 볼 것
  1. 일반 사용자 둘로 확정된 일정 → 받는 쪽 "내 QR 보여주기": 30초마다 QR·번호가 바뀌는지, 봉사자가 찍으면 시트가 닫히는지, 1분 전 번호는 거절되는지.
  2. 관리자 스케줄러 실행(또는 1분 대기)으로 시작 10분·30분 뒤 알림이 양쪽에 오는지, 30분 뒤 "노쇼 신고·취소"가 열리는지.
  3. 활동 중인 일정이 예정 종료 30분 뒤 "활동 끝(자동 마감)"으로 바뀌고 봉사자에게 일지 알림이 오는지.
  4. 담당자: 도움 대상 → "현관 QR 카드" 보기·인쇄·다시 발급. 봉사자가 이전 카드 번호로 시작하면 거절되는지.
  5. 독거노인 활동에서 봉사자 "이상 징후(안부 확인) 알리기" → 담당자 알림 → 운영자 "안부 확인 접수" 구역에서 "기록 확인"만 되는지.
  6. 알림 목록에서 신고 결과·문의 답변 알림을 누르면 문의·신고 내역으로 가는지.

맞춘 것
- **11번 긴급 시트**: 제목 "긴급 상황인가요?", 본문 "다쳤거나 위험하면 먼저 119·112에 전화해 주세요.", 버튼 [📞 119 전화] [📞 112 전화] [운영자에게 신고 접수하기] [닫기], 아래 "신고는 운영자가 확인하고 처리해요. 급한 일은 119·112가 먼저예요." — 프로토타입 배치·문구 그대로. 전화 버튼은 시연 토스트 대신 실제 전화 연결(`tel:`).
- 신고 접수 문구 "신고를 접수했어요. 운영자가 확인해요".

프로토타입과 다르게 둔 것(명세를 따름)
- 프로토타입의 "운영자에게 신고 접수하기"는 누르면 바로 접수된다. 명세 B-37이 유형 선택과 내용 입력을 요구하므로 신고 양식을 연다. 독거노인 활동이면 양식 맨 위에 "이상 징후(안부 확인)"가 먼저 골라져 있고, 긴급 시트 아래에 그 안내 한 문장을 덧붙였다(B-36: 담당자 알림).
- 프로토타입에 없는 화면(30초 QR 남은 시간, 현관 카드 다시 발급, 운영자 안부 확인 구역, 방문 중 안전 규칙 띠)은 지금 화면의 클래스로 만들었다.

못 맞춘 것
- 프로토타입 파일 전체를 내 범위 화면과 한 줄씩 대조하지는 않았다. 총괄이 짚은 11번·14번과 `sos` 묶음만 직접 확인했다.
