## ② 새 API · 바뀐 API

**새로 생김**
- `POST /api/posts/{id}/repost` 본문 `{ "date": "YYYY-MM-DD" }` → 새 공고 카드(PostCard + `repostOf`: 원래 공고 번호). 지난 공고(마감·매칭된 것 포함, 삭제된 것 제외)를 같은 내용으로 날짜만 바꿔 1건 올린다. 쓸 수 있는 사람: 공고 주인, 그 독거노인의 담당자, 가족 대신 올린 작성자. 오류: 날짜 없음·지난 날짜 400 `INVALID_DATE`, 남의 공고 403, 삭제된 공고 404, 종료된 대상 400 `ELDER_ENDED`.

**바뀜**
- `POST /api/posts`
  - `repeat`: 받기는 하지만 **무시**한다(글자·객체·true 모두). 항상 1건. 응답 `createdCount`는 늘 1, `createdIds`는 1개. 반복을 바랐으면 응답에 `repeatNotice`(안내 문장).
  - `forUserId`(새, 선택): 연결된 가족의 회원 번호. 주면 가족 대신 올리는 도움 요청 공고. 오류: 연결(ACCEPTED) 아님 403, `type`이 NEED가 아님 400 `INVALID_TYPE`, 본인 번호·정지 계정 400 `INVALID_FAMILY`.
- `GET /api/posts`: 새 쿼리 `lat`, `lng`(둘 다 있어야 함, 틀리면 400 `INVALID_LOCATION`), `dateFrom`, `dateTo`. 좌표가 오면 카드의 `distanceKm`이 그 좌표에서 공고 동네 중심까지 거리로 바뀌고 `distanceBy: "location"`, 아니면 `"profile"`(예전 방식).
- `GET /api/posts/mine`: 새 쿼리 `elderId`(그 대상의 공고만). 내가 가족 대신 올린 공고도 포함(`proxyMine: true`).
- `GET /api/posts/{id}`: 가족 대신 올린 작성자에게도 `requests`(읽기용, `myRole` null·`actions` 빈 목록)를 준다.
- PostCard에 새 칸: `proxy`(가족 대신 올린 공고인가), `proxyByName`(올린 사람 이름), `proxyMine`(보는 사람이 올린 사람인가) — 목록·내 공고·상세·등록 응답에만 붙는다. `repeatRule`·`seriesId`는 남아 있지만 새 공고에서는 늘 null.
- `POST /api/ai/post-chat` 응답 `draft`: `repeat` 칸 삭제, `repeatNotice`(안내 문장 또는 null) 추가.
- `POST·PUT /api/interest-alerts`: 본문에 `dateFrom`, `dateTo`("YYYY-MM-DD", 빈 글자면 지움). 응답 InterestAlert에도 같은 칸. 끝<시작·모양 오류는 400 `INVALID_DATE`.
- 새 알림 종류 `FAMILY_POST`(가족에게, 링크 `/posts/{id}`).

**담당자 화면 진입점(다른 담당이 붙일 것)에 필요한 모양**
- 대상의 지난 요청 목록: `GET /api/posts/mine?elderId={대상 번호}` (날짜 내림차순, 마감된 것 포함)
- 다시 올리기: `POST /api/posts/{공고 번호}/repost` `{date}`. 프런트는 `import { useRepost } from '../ui/repost.jsx'` 후 `repost(공고카드, (새공고) => …)`를 부르면 날짜 고르는 시트까지 그대로 쓸 수 있다.
- 관심 조건 화면(`my.jsx`)의 날짜 칸: 위 `dateFrom`·`dateTo`를 보내면 된다.
- 가족 대신 봉사 요청 진입(`my.jsx`): 지금 `/write/need?family=이름`도 동작하지만 `/write/need?familyId={회원 번호}`가 정확하다(이름이 같은 가족 구분).

## ④ 못 한 것 · 남은 것 · 알아 둘 것

- **동별 좌표 표가 가상 좌표다.** `service/Geo.java`는 시범 5개 동(행복동 등)을 서울시청 근처 기준점에 놓은 값이다. 실제 위치가 그 근처가 아니면 모든 공고가 수백 km로 나온다(순서는 맞음). 실제 서비스 지역이 정해지면 이 표만 바꾸면 된다. 표에 없는 동의 공고는 예전처럼 프로필 동네 기준 거리로 남는다.
- **가입 때 위치 정보 선택 동의와는 연결하지 않았다**(`users` 동의 칸은 A-01 담당). 지금은 브라우저 권한만 본다.
- **관심 조건 알림 링크**(`/posts/{id}` ↔ 화면 `/post/:id`)는 `common.jsx`(다른 담당) 쪽이라 고치지 않았다. 새 `FAMILY_POST` 알림도 같은 `/posts/{id}` 모양이다.
- **담당자 화면**(`org.jsx`)의 "지난 요청 다시 올리기" 진입점, **마이 화면**(`my.jsx`)의 관심 조건 날짜 칸·가족 여럿 고르기 메뉴는 만들지 않았다(다른 담당). 필요한 API는 ②에 있다.
- **가족 대신 공고에서 내가 판단한 것(확인 필요)**: 올린 사람도 수락 전에는 자기가 쓴 공고를 수정·삭제·다시 올리기 할 수 있게 했다(총괄 결정 "올린 사람은 진행 상황을 읽기만"은 요청 진행에 대한 것으로 읽음). 막으려면 `PostService.canEdit`의 `isProxyAuthor` 한 줄을 빼면 된다.
- 올린 사람이 그 가족 공고에 직접 봉사 제안을 보내는 것은 막지 않았다(`RequestService`를 건드리지 않음).
- 가족 대신으로는 단골 요청을 보낼 수 없어, 가족 대신 작성에서는 "누구에게" 질문을 건너뛴다. 기관 클래스에서 문장을 미리 채워 들어온 경우(`prefill`)도 건너뛴다.
- 담당자 통화 메모 → 공고 여러 건(`OrgAi.memoToPosts`)의 초안에는 `repeat` 칸이 그대로 있다(서버는 무시). 화면의 체크만 안내 문장으로 바꿨다. 초안에서 칸을 지우는 것은 담당자 범위.
- `DataSeeder`가 넣는 시범 공고 4건에는 `repeat_rule`이 남아 있다(화면에는 더 보이지 않음).
- 화면은 빌드만 확인했고 브라우저에서 눌러 보지는 않았다(위치 권한 창·시트 동작은 실제 기기 확인 필요).

## ⑤ 확인 방법

- 백엔드: `cd backend && sh ./mvnw -q test` — 24개 묶음 154건 통과(2026-11-12). 이 범위 테스트: `Req41PostTest`(11건, 새), `VoiceRepeatTest`(5건, 새 동작으로 고침), `FlowIntegrationTest.반복_칸이_와도_공고는_한_건만`.
- 프런트: `cd frontend && npm run build` 성공.
- 손으로 볼 것
  1. 공고 올리기 → 도움 가능: 반복 체크가 없고 [지난 공고 불러오기]가 있다. 고르면 칸이 채워지고 날짜를 고르라는 안내가 뜬다.
  2. 내 공고 상세 → "같은 내용으로 다시 올리기" → 날짜 시트 → 고른 날짜로 새 공고 1건.
  3. 봉사 요청(`/write/need`), 말로 요청하기(`/voice`): 처음에 "누구에게 도움을 청할까요?"가 뜨고, 단골을 고르면 단골 요청 화면으로 간다. "매주 목요일 오전 10시 말벗"이라고 하면 1건만 올라가고 다시 올리기 안내가 보인다.
  4. 가족 연결된 두 계정: 마이 → 가족 대신 봉사 요청 → 올리면 공고가 가족 이름으로 보이고, 봉사 제안의 수락 버튼은 가족 계정에만 있다. 올린 계정의 공고 상세에는 "보기만" 목록.
  5. 공고 목록: 정렬 칩을 누르면 위치 권한 창 → 허용하면 "가까운 순", 거절한 뒤 다시 누르면 허용 방법 시트. 날짜 칩 → "날짜 고르기".
  6. 공공 서비스 안내: 질문을 보내면 위치를 묻고, 거절하면 동네 기준으로 찾았다는 안내가 보인다.
