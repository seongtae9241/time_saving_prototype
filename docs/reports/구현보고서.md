# 시간 적금 구현 보고서

작성일: 2026-11-09 · 저장소: `seongtae9241/time_saving_prototype`

## 1. 요약

- 요구사항명세서의 **요구사항 91개(A-01~D-09 84개 + 추가 제안 P-01~P-07)**를 기준으로 백엔드(Spring Boot)·프론트엔드(React)·DB를 새 프로젝트로 만들었습니다.
- 화면·흐름·문구·디자인은 **황수빈 님 프로토타입(첫 활동 교육·동네 클래스판)**을 채택해 옮겼습니다. 나머지 3개 프로토타입은 채택안에 화면이 없는 요구사항을 만들 때만 참고했습니다.
- 사용자 요청으로 프로토타입에 없던 **"말로 요청하기"(음성 → 요청서)**를 추가했습니다.
- 실제 서버를 띄워 **사용자·담당자·운영자 3역할 주요 흐름을 브라우저로 끝까지 확인**했습니다. 백엔드 테스트는 **34개 모두 통과**합니다.
- AI 키가 없어도 모든 기능이 **규칙 모드**로 동작합니다. 키를 넣으면 Claude로 바뀝니다. 개발·테스트 중 실제 AI 호출은 하지 않았습니다(비용 0원).

| 항목 | 규모 |
|---|---|
| 백엔드 | 자바 87개 파일·약 6,900줄, 엔티티 25개, 컨트롤러 9개, 테스트 34개 |
| 프론트 | 화면 파일 14개·약 5,600줄, 채택안 화면 59개 전부 + 요구사항 보충 화면 14개 + 음성 요청 화면 |
| DB | 테이블 25개(`db/schema.sql`), ERD(`db/README.md`) |

## 2. 만든 방법 (진행 순서)

1. **요구사항·프로토타입 분석**: 엑셀 요구사항명세서를 글로 뽑아(`docs/requirements/요구사항명세서.txt`) 액터·기능을 정리했습니다. 채택 프로토타입의 화면 59개(`SCREENS.*`), 역할별 탭, 시드 데이터(`D`), 교육·클래스 규칙을 읽었습니다.
2. **구현 계약서 작성**(`docs/design/contract.md`): 백엔드와 프론트를 동시에 개발하기 위해 다음을 먼저 정했습니다.
   - 기술 구성
   - 적립·상태 흐름 규칙
   - 테이블 25개
   - API 약 145개 엔드포인트
   - 데모 계정
   
   요구사항과 프로토타입이 부딪히면 **요구사항이 우선**이라는 원칙도 이때 정했습니다. 예를 들어 프로토타입은 독거노인 실명을 보여 주지만, 요구사항 C-02에 따라 별칭만 저장합니다.
3. **백엔드·DB와 프론트를 두 개발 담당이 동시에 개발**: 계약서에 없는 것을 더하면 계약서 7절에 기록하게 해서 서로 맞췄습니다.
4. **음성 입력 추가**(사용자 요청): 분석 보고서(`docs/reports/음성입력-분석보고서.md`)를 쓰고, 그 내용(의도·확신도·위급·개인정보 처리)을 개발 중인 코드에 바로 반영했습니다.
5. **통합 확인**: 총괄이 직접 서버를 새 DB로 띄웠습니다.
   - 프론트 담당이 찾은 백엔드 문제 3건을 확인하고, 실제 버그 2건을 고쳤습니다(6장).
   - 설정 1건을 고쳤습니다(다른 포트 개발 서버 CORS).
   - 화면을 브라우저로 열어 오류를 확인했습니다.
   - 프론트를 jar에 넣는 빌드 스크립트를 만들었습니다.

## 4. 시스템 구조

```
[브라우저 · React(모바일 화면)]
   │  /api/* (JSON, Bearer 토큰)
   ▼
[Spring Boot]
   ├─ 컨트롤러 9개: Auth, Post, Request, Bank, Ai, Common, EduClass, Org, Admin
   ├─ 서비스: PostService, RequestService(상태 흐름), BankService(통장), SchedulerService(1분마다),
   │          LifeReportService, ClassService, EduService, NotificationService, DataSeeder
   ├─ ai/AiClient ── 키 있음 → Claude API(claude-haiku-5-5)
   │               └ 키 없음·실패 → RuleEngine / KoreanParser / PostChatRule / VoiceSafety (규칙 모드)
   ▼
[DB · H2 파일(기본) / MySQL(프로필)]  테이블 25개
```

- **인증**: 로그인하면 토큰을 발급하고 `auth_token` 테이블에 저장합니다. 토큰은 30일, "로그인 유지"를 고르지 않으면 1일 동안 유효합니다. 역할(USER/ORG/ADMIN)마다 API 접근을 막습니다. 비밀번호는 BCrypt로 저장합니다.
- **스케줄러**(1분 간격, 운영자 화면에서 즉시 실행 가능):
  - 24시간 응답 기한이 지나면 자동 만료(B-19)
  - 날짜가 지난 공고 자동 마감(B-11)
  - 일지 제출 뒤 24시간이 지나면 자동 확정(C-10)
  - 시작 15분이 지나도 체크인이 없으면 알림
  - 시작 전날 리마인드
  - 매월 1일 생활 변화 리포트 생성(P-03)
- **단일 실행**: `scripts/build.sh`가 프론트 빌드 결과를 백엔드에 넣어 jar 하나로 만듭니다. 화면 경로는 SPA로 연결됩니다.

## 5. 기능별 구현 내용

### 5.1 핵심 규칙 (서버가 강제)
- **적립** = 활동 시간 × 난이도 가중치이고, 0.5 단위로 반올림합니다(B-26).
  - 가중치: 기본 1.0 / 수고 1.2 / 책임 1.5(B-27)
  - 여러 일이 섞이면 가장 높은 등급 기준(B-29)
- **상태 흐름**(A-05):

  ```
  요청·제안 → 봉사자 수락 → 받는 사람 최종 수락 → 체크인(6자리 코드·QR) → 체크아웃
           → 활동 일지 → 확인 → 적립·차감 → 평가
  ```
  - 공고 1건이 수락되면 나머지 요청·제안은 자동 거절됩니다(B-17).
  - 최종 거부나 만료로 끝나도 공고는 다시 열리지 않습니다(B-19).
- **시간 통장**:
  - 확정되면 받는 사람의 시간을 보류하고, 완료되면 차감합니다(B-30).
  - 독거노인 건은 차감 없이 봉사자만 적립됩니다(B-31).
  - 본인이 적립한 시간이 10시간 이상이어야 쓸 수 있습니다. 선물받은 시간은 예외입니다(B-33).
  - 선물은 연결된 가족에게만 보낼 수 있습니다(B-32, B-34).
- **취소·노쇼**: 시작 24시간 전까지는 무료 취소입니다. 그 뒤 취소하거나 노쇼하면 패널티가 쌓입니다(B-25).
- **독거노인 개인정보 최소화**:
  - 별칭·동·도움 유형·주의사항만 저장합니다. 이름·주소·연락처를 입력하면 막습니다.
  - 봉사자 화면에는 "이○례 님"처럼 가려서 보입니다(B-13, C-02).
- **단골**: 같은 상대를 3회 이상 도우면 단골 배지가 붙고, 단골에게 요청하기에 쓰입니다(B-41, B-14).

### 5.2 AI 기능 (전부 `AiClient` 한 곳을 지남)
| 기능 | 요구사항 | 규칙 모드에서의 동작 |
|---|---|---|
| 대화형 공고·요청서 작성 | B-02 | 빠진 항목(날짜→시간→장소→내용)을 하나씩 되묻고 JSON 초안을 만듦 |
| 금지 요청 필터 | B-09 | 신체 돌봄·의료·금전·위험 작업은 불가, 공공 서비스 DB로 대체 안내 |
| 난이도 제안·예상 적립 | B-08, B-27 | 6개 요소의 키워드로 등급과 근거를 제안하고, 가중치는 규칙으로 적용 |
| 활동 일지 정리 | B-24 | 한 줄 기록을 2~3줄 일지로 다듬음 |
| 공공 서비스 안내(RAG) | P-01 | DB 검색 결과만으로 설명. 없는 서비스는 만들지 않고 자격 판정도 하지 않음 |
| 생활 변화 리포트 | P-03 | 숫자는 코드가 집계하고, 문장은 템플릿으로 씀. 진단은 하지 않음 |
| AI 도움 추천 | 프로토타입 | 상황 문장 → 카테고리·공고 추천 |
| 교육 역할극 판정 | 프로토타입 | 연락처·금전·신체 돌봄·개인정보 위반을 판정하고 소통·공감 점수를 매김 |
| **말로 요청하기** | 추가(사용자 요청) | 7장 |

### 5.4 DB
- 테이블 25개는 계약서 4장과 `db/README.md`(mermaid ERD)에 정리돼 있습니다.
- `db/schema.sql`은 실제 엔티티에서 뽑은 MySQL 호환 DDL입니다.
- 기본은 H2 파일 DB(MySQL 모드)입니다. `mysql` 프로필로 MySQL 8에 바로 연결할 수 있습니다.
- 데모 데이터는 DB가 비어 있을 때만 들어가고, 날짜는 오늘 기준 상대 날짜입니다.
  - 프로토타입 인물(손유진·김하늘·최미경·이도윤·김복남·이순자)
  - 담당자 2명과 도움 대상 4명
  - 공고, 여러 상태의 요청, 통장 내역
  - 클래스 5개, 역할극 상대 3명, 퀴즈 5문제
  - 공공 서비스 10개: 실제 서비스 이름만 쓰고, 세부는 "기관 확인 필요"로 적었습니다.
  - 지난 5달 활동

| 화면 오류 점검 | 세 역할 주요 화면 14개를 새 DB에서 열어 화면 오류·서버 500 0건 |
| jar 하나 실행 | `scripts/build.sh` → `java -jar`로 화면과 API가 함께 열림 |

통합 중 고친 것:
1. 지역이 없는 담당자 계정으로 공고 목록·대리 공고·대상 상세를 열면 서버 오류(500)가 났습니다. 거리 계산의 빈 값 처리를 고쳤습니다.
2. 도움 요청 공고에 활동 시간을 안 보내면 400이 났습니다. 이제 시간 범위(최대 4시간)로 자동으로 채웁니다.
3. 개발 서버 CORS가 5173 포트만 허용했습니다. `localhost` 모든 포트를 허용하도록 바꿨습니다.
4. 프론트 담당이 "공공 서비스 대체 안내가 비어 있다"고 보고했습니다. 새 DB에서 확인해 보니 10개가 들어 있고 안내도 정상이었습니다. 담당자가 쓰던 이전 DB 때문이었던 것으로 보입니다.

## 7. 추가 기능: 말로 요청하기 (사용자 요청)

프로토타입의 마이크 버튼은 4곳 모두 "테스트 중" 안내만 떴습니다. 이번에 실제로 동작하게 만들었습니다.

- **흐름**:

  ```
  홈 큰 마이크 카드
    → 브라우저 음성 인식(한국어) 받아쓰기: 말하는 동안 글자가 보임
    → AI가 요청서로 정리
    → 빠진 것을 소리로 하나씩 되물음
    → 요청서 카드를 큰 글씨로 보여 주고 소리로 읽어 줌
    → 큰 버튼 "이대로 올리기"
  ```
- **안전장치**:
  - 자동 등록은 하지 않습니다.
  - 위급 표현이 나오면 흐름을 멈추고 "119 전화하기" 버튼을 띄웁니다.
  - 전화번호·계좌·상세 주소는 요청서에서 지웁니다.
  - 병명은 저장하지 않습니다.
  - 금지 요청이면 공공 서비스를 안내합니다.
  - 되묻기가 3번을 넘으면 큰 선택 버튼(날짜·오전/오후·카테고리)으로 바꿉니다.
- **대리 작성·대체 입력**: 담당자 대리 작성에서도 같은 화면을 씁니다(`/voice?elder=`). 음성 인식이 안 되는 브라우저에서는 큰 입력칸으로 같은 흐름을 탑니다.
- 설계 근거와 다음 단계(서버 음성 인식, 전화 접수)는 `docs/reports/음성입력-분석보고서.md`에 있습니다.
