# 기관 담당자 프로토타입 품질 검증·개선 최종 보고서 (2026-11-23)

대상: `docs/prototypes/proto-2026-11-20-기관담당자-PC-11.html` (이하 "11판")
범위: 내 파트(기관 담당자) 프로토타입과 그 명세서. 실제 앱(`frontend/`, `backend/`)은 이번에 고치지 않았고 빌드만 확인했다.
세부 근거: 같은 폴더의 1~3차 검증·감사 보고서, 수정 1·3·6회차, 기능추가 2회차, 코드정리 4회차, 디자인 5회차 문서와 `docs/qa/shots/`.

## 1. 프로젝트 현황 분석
- **기술 스택**
  - 실제 앱: React 18 + Vite 5 + react-router 6, JavaScript(TypeScript 없음). 백엔드는 Spring Boot 3.5 / Java 21 / JPA, 단위 테스트 42개 파일.
  - 프로토타입: 단일 HTML 파일. 바닐라 JS, 해시 라우팅, 템플릿 문자열로 화면을 그리는 `render()` 구조. 외부 라이브러리는 없다.
- **구조**
  - 화면(경로): 홈, 특보 알림, 관리 대상(+상세), 돌봄 편성표(월 달력·사람별), 요청 관리(보드·목록·상세 채팅), 정기 요청, 공공 서비스 연계, 기관 공고, 기관 행사, 기관 클래스, 리포트, 담당자 계정, 권한 위임, 알림, 내 정보, 1:1 문의, 봉사 신청서, 도움 찾기.
  - 공통 요소: 서랍, 확인 창, 토스트, 카드 끌기 배치(줄 단위, 담당자별 저장), 1단·2단 보기, 모바일 상단 줄.
- **시작 시점에 발견한 구조 문제**
  - CSS 덧붙임 층이 23개 쌓였고 `!important`가 1,195개였다. 규칙의 약 60%가 화면에 영향이 없었다.
  - `render`가 12겹으로 감싸져 있었다.
  - 같은 일을 하는 코드가 여러 벌 있었다: 배치 저장 3곳, 현재 화면 구하기 6곳, 넘침 검사 2개.
  - 행사 상세가 순번으로 연결되어 있어, 새 행사를 올리면 상세 내용이 밀렸다.
  - 화면마다 숫자가 서로 맞지 않았다.
- **실행·빌드**
  - 실제 앱 `vite build`: 성공(번들 500KB 경고만 있음).
  - 프로토타입: 빌드 없이 브라우저에서 바로 연다.

## 3. UI/UX 검수 결과 (주요 개선)
- **입력 확인**
  - 모든 양식이 칸 아래에 오류 문장을 보여 주고, 첫 오류 칸으로 초점을 옮긴다. 대상은 봉사 신청서, 관리 대상 등록, 행사·클래스, 단체 공고, 담당자 계정, 비밀번호, 문의.
  - 위험한 동작은 확인 창을 거치고, 초점은 '취소'에 둔다.
- **피드백·빈 상태**
  - 동작마다 토스트를 띄운다. 어두운 화면의 토스트 대비 문제도 고쳤다.
  - 필터로 0건이 되면 이유와 '필터 풀기'를 보여 준다.
- **배치**
  - 카드를 끌어 1분할·2분할로 놓을 수 있다. 띠도 끌 수 있고, 담당자별로 저장된다.
  - 본문이 좁으면 자동으로 1단이 된다.
  - 카드가 좁아지면 표가 카드형 줄로 바뀐다.
  - 모바일은 상단 줄과 메뉴 서랍으로 바뀐다.
- **일관성**
  - 숫자는 모두 자료에서 계산한다. 홈 칩 합계가 전체와 같고, 특보 인원도 화면마다 같다.
  - 단계·용어를 통일했다: 요청→수락→활동 중→일지→완료, 채팅, 봉사 신청서, 담당 넘기기, 담당자 계정.
- **디자인**
  - 팀원 콘솔 구조에 사용자 쪽 디자인을 입혔다: 채팅 목록 카드, 날짜 타일, 아이콘 타일, 티켓 머리, 타임라인.
  - 코랄 강조색과 탭 규칙을 유지했다.
- **접근성**
  - 서랍 안에서 초점이 갇히고, 닫으면 연 버튼으로 돌아온다. Esc로 닫힌다.
  - 탭은 ←/→로 이동하고, 라벨이 입력 칸과 연결되어 있다.
  - 대비 스캔 125상태(밝게·어둡게)에서 4.5:1 미만은 0건이다. 글자 없는 조작 요소도 3:1 이상이다.

  - 행사·클래스 상세를 id로 연결했다.

- **화면 동일성 확인**

## 8. 미해결 문제 및 권장 사항
- **외부 의존성**: 실제 API·DB(명세의 '추가 필요' 항목), 이메일 발송(운영자의 임시 비밀번호), 실제 QR, 음성 인식.
- **다른 파트**: 기관 신청(가입 때 계정 3개), 운영자의 임시 비밀번호 발급 화면, 알림 담당 결정.
- **기획 확인**: 비식별 전처리 기준, 채팅 실시간 방식, 다른 담당자 대상에게 대신 행동하는 범위, 평가 3일 기준 시각.
- **정식 개발 단계 권장**
  - 프로토타입 화면을 실제 앱(`frontend/src/screens/org*.jsx`)의 React 컴포넌트로 옮긴다. 공통 부품으로 쓸 것은 DateTile, CategoryTile, ChatListCard, TicketHeader, 확인 창, 양식 검증이다.

  - CSS 토큰 체계로 다시 설계해 `!important`를 없앤다.
  - 인라인 핸들러를 이벤트 위임으로 바꾼다.
