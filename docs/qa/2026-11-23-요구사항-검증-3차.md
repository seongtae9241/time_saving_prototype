- **검증 대상**: `docs/prototypes/proto-2026-11-20-기관담당자-PC-11.html`
  - 3회차 수정·4회차 코드 정리·5회차 디자인을 반영한 판(6629줄).
  - 예시 데이터만 있고 서버는 없어요. **API는 검증하지 않았고**, 화면 동작만 확인했어요.

  - 새 사용자 결정 7건은 **D01~D07**로 번호를 붙여 따로 확인했어요.
- **새 결정과 부딪히는 명세 행**은 CONFLICT가 아니라 **'명세 수정 예정'**으로 적었어요.
  - 예: 대신 최종 수락, 승인/거절, 6·7단계 이름, '도움 요청서' 이름, 휴대폰 본인인증 신청.
  - 화면이 새 결정대로 동작하면 '명세 수정 예정'으로 세고, PASS와 따로 셌어요.
- **검증 방법**
  - Playwright Chromium. 브라우저는 한 번에 하나만 띄웠어요.
  - 화면 폭: 1440×900, 1280×800, 1280×2000·1440×2000(끌기용), 390×844. 어두운 화면은 1440·390에서 일부 확인했어요.
  - deviceScaleFactor 1. 상태마다 localStorage를 비웠어요.
  - 실제로 클릭·입력·키보드를 썼어요. 끌기는 page.mouse로 down → 단계별 move → up 했어요.
  - 1·2차 스크립트 일부를 다시 돌렸고, 새 스크립트 18개(v1~v18)를 썼어요.
- **오류·넘침**
  - 경로 25개 × (1440·1280·390·1440 어둡게·390 어둡게): `pageerror` 0건, 가로 넘침 0건, 13px 미만 글자 0건.
  - 콘솔 오류는 막아 둔 외부 글꼴 요청의 `ERR_FAILED`뿐이에요.
- **도구 참고**
  - 일부 본문 버튼은 Playwright `locator.click()`이 끝나지 않고 걸렸어요.
  - 같은 버튼을 실제 마우스 좌표로 누르면 정상 동작했어요(`elementFromPoint`도 버튼 자신, 툴팁 `#ctip`은 `pointer-events:none`).
  - 화면 결함이 아니라 테스트 도구 쪽 문제로 보고, 좌표 클릭으로 검증했어요.
