# 시간 적금 · 담당자 화면 규칙

사용자(담당자 화면 주인)와 팀이 여러 번 되풀이해 말한 것을 모았다. 새 화면·수정·검토 모두 이 규칙으로 본다.
기준 시안: `docs/prototypes/proto-2026-11-16-기관담당자-PC-2.html` (디자인 참고 원본은 `docs/prototypes/ref-운영자콘솔-2026-11-16.html`).

## 배치
- **중요한 것이 위·왼쪽.** 그 화면에 온 목적(지금 처리할 일 → 위험 신호·먼저 살펴볼 분 → 오늘 일정)이 첫 화면에 보여야 한다. 통계·바로가기·설명 글은 아래.
- **한 번에 너무 많이 보여 주지 않는다.** 첫눈에 들어오는 덩어리는 3~4개. 나머지는 접힘·탭·서랍·"더 보기"로 차근차근. 목록은 5~7줄 + 더 보기, 긴 폼은 단계로 나눈다.
- **구역마다 주 버튼은 1개.** 상세 화면은 "단계 막대 + 다음 할 일 상자(주 버튼 1개)"가 먼저, 기록·부가 정보는 아래.
- 사람이 짠 것처럼: 같은 크기 카드를 격자로 찍어 내지 않는다. 주된 영역 1개 + 보조 영역, 위계를 분명히.
- 관련된 것끼리 가까이. 누른 결과가 화면 밖에 뜨면 안 된다(필요하면 그 자리로 스크롤).

## 여백·크기
- **본문을 꽉 채우지 않는다.** 본문 최대 폭 1080px, 가운데 정렬, 양옆 여백(`--gut`). 폼은 내용에 맞는 폭(520~640px).
- **쓸데없이 큰 것 금지.** 상자·버튼·숫자·입력칸은 내용 크기에 맞춘다. 빈 상태는 한 줄. 나란한 카드는 높이를 맞춘다.
- "딱 봐도 이상한 모양"을 내보내지 않는다: 폭이 혼자 다른 칸, 혼자 떨어진 버튼, 빈 큰 상자, **글을 덮는 떠 있는 버튼·알림**(떠 있는 요소 대신 머리줄 버튼, 알림 문구는 위쪽).
- 돌봄 편성표: 달력이 주인공, 옆 칸들은 달력 아래. 빈칸을 누르면 달력 바로 아래에 대안이 보인다.

## 색·그래프·꾸밈 (2026-11-18 사용자 결정으로 고침)
- **색은 단일 파스텔 톤으로 유지**(사용자 결정). 강조색 한 가지(코랄 또는 라벤더, 팀이 고르는 중)의 진하기·연하기로 화려함을 낸다. 종류마다 다른 색 타일, 이름별 무지개 아바타처럼 여러 색을 섞지 않는다.
- 뜻 색(요청 파랑·확정 초록·위험 빨강·주의 호박·AI)은 상태를 알릴 때만, 작게.
- 아래는 총괄이 임의로 붙였던 제약이라 **풀었다**(사용자: "나머지는 규칙 풀고 마음껏"): 첫 화면 그래프·숫자 카드 노출 가능, 진행 링·도넛 가능, 외부 글꼴 추가 가능, 직접 그린 그림·일러스트 가능, 홈 단계 띠를 큰 카드로 가능, 줄 호버·등장 움직임 풍부하게 가능.
- 그래도 남의 그림·아이콘·코드를 가져오지 않고 직접 그린다. 이모지는 쓰지 않는다(선 아이콘·직접 그린 그림).
- 그래프에는 축·단위·기간·"무엇을 센 것"을 알 수 있게 한다.

## 사용자·팀이 직접 말한 것 (풀지 않는다)
양옆 공간 남기기 · 중요한 것이 위에 먼저 · 한 번에 너무 많이 보여 주지 않고 차근차근 · 쓸데없이 큰 컴포넌트는 내용에 맞게 · 사람이 짠 것처럼, 딱 봐도 이상한 모양 없게(글을 덮는 요소·혼자 다른 폭·빈 큰 상자) · 눈이 피곤하지 않게(작은 글씨·약한 대비·빨강 남발 금지).

## 서비스 원칙 (화면에도 그대로)
- AI는 안내, 결정은 담당자. AI가 쓴 것("AI 안내" 태그 + 근거 줄)과 담당자가 쓴 기록을 구분해 보여 준다. 상대에게 알림이 가는 일은 확인 창.
- 진단하는 말 금지("확인해 보세요" 수준). 숫자는 기록으로 계산한 값, AI는 설명만.
- 실제 앱: 관리 대상은 별칭·나이대·동만(실명·전화·주소 저장 안 함). 1시간=1시간, 가중치 없음.

## 내보내기 전 확인
- 고친 화면은 1440×900과 좁은 폭(약 1190)에서 **사진을 직접 보고** 겹침·넘침·가림·줄 안 맞음을 잡는다. 스크립트 오류 없음만으로 끝내지 않는다.
- 숫자가 화면끼리 맞는지(홈 ↔ 메뉴 배지 ↔ 상세) 본다.
